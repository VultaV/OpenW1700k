# r70 — Drain offload work before callback removal; restore stock NPU0.8

The r69 four-byte zero-budget guard is withdrawn. It reproduced a runtime downlink stall and has no demonstrated benefit. Static instruction equivalence for positive budgets did not establish the vendor meaning of zero or service fairness at the caller's output-slack7 state. Neither a firmware bug nor guard-induced causality is claimed. r69 remains immutable with a not-recommended warning.

The exact vendor program is restored: SHA256 `7068a987bb95e89129a69de10d598f234a4400023eb23aacc8eb377e5f0fe0ea`,125832 bytes. Data remains `6fd9506e399ebb309801ac2ecc74d3e10fa66731afc828c76fde8a67b2153f49`,3092 bytes. Package0.8-r3 supersedes0.8-r2, while the firmware version string remains0.8. The kernel uses new common ABI6.18.59-w1700k-mlo-r70 for the offload cleanup change. The16MiB coherent pool, original QDMA, mt76r42, hostapd/wpad r9 and Wi-Fi firmware are retained. This is not a new upstream firmware.

Stock program identity and2 actual loader/probe cases pass with ASan/UBSan. The old0.7 identity-specific loader guard remains inactive. Candidate-only0.8 guard tests remain in the immutable r69 tag and are removed from current source. Build, packaged byte equality and boot/traffic checks are recorded separately. Results measured on r67 are explicitly r67 controls, not r70 results. MLO stability is not proved solved; true weak-signal fallback, full OS sleep and overnight operation remain untested.

The2026-10-26 pre-unbind cleanup proposal is backported, retaining existing hook/error/netdev and BIND/UNBIND lifecycles. The current baseline can unbind callbacks before delayed flowtable destruction; later hardware deletes then have no callback. Cleanup plus a second GC and delete-work flush runs before unbind.13 host cases/2 negative controls and22 bridge cases pass. No concrete Airoha/NPU lock cycle was found in the reviewed paths, but arbitrary concurrency/OOM is not proved. This does not establish that orphan hardware entries caused the measured throughput failure. The later hook-release rewrite was not adopted because netdev/error cases require further review.
