## 시험에 영향을 준 패널 상태

초기 macOS **시스템 설정 → Wi-Fi 패널은 시험 담당 에이전트가 열어 둔 상태**였다. 이를 다른 설정 패널로 전환한 뒤 300초 평균이 1,318.8Mbps에서 1,952.6Mbps로 바뀌었고, 다시 열고 닫은 60초 비교에서도 1,365.5Mbps와 1,964.1Mbps로 차이가 반복됐다. 이 비교에서 Wi-Fi 재연결이나 공유기 설정 변경을 의도적으로 수행하지 않았다.

재열림 60초 시험의 저속 구간 7–11초, 23–27초, 39–43초, 55–58초에는 각각 PS 이벤트 집중 구간 6.792–9.193초, 22.755–24.656초, 38.952–41.220초, 54.671–56.836초가 겹쳤다. 재닫힘 시험에는 시작 근처 3개·종료 근처 1개의 PS 이벤트가 있었고 같은 중간 반복 양상은 없었다. 재열림의 PS 이벤트 번호 누락 합계는 300, 재닫힘은 0이었다. 이는 아래 전체 진단 창의 callback 억제 합계 322와 범위·집계 방식이 다르다.

연속 이벤트 번호의 gate 1→0 쌍 128개의 host 로그 간격은 최소 1.454ms, 중앙 50.704ms, 최대 201.597ms였다. 이 간격이나 이벤트 집중 구간을 펌웨어에서 PS=1이 연속 3초 유지됐다는 증거로 취급하지 않는다.

이 조작은 측정에 영향을 준 조건으로 기록한다. 순서가 무작위화되지 않았고 무선 스캔·단말 스케줄링을 별도로 분리한 실험은 아니므로, 패널 내부의 정확한 원인이나 r39 수정 효과로 단정하지 않는다. 같은 시험 세션의 r32 대조군도 없다. 주로 6GHz 경로를 사용한 이번 MLO 연결은 5GHz와 6GHz의 동시 데이터 합산을 입증하지 않는다.

## PS 진단 기록과 최종 복원

표시한 PS 진단 창에서 방출된 커널 로그 **1,179개**의 sequence가 연속이었다. 그러나 rate limit 알림 5개에 **60 + 112 + 60 + 68 + 22 = 322개 callback 억제**가 기록됐다. 따라서 방출된 로그의 연속성은 모든 PS 이벤트의 수집을 뜻하지 않는다. 특정 이벤트가 기록되지 않았다는 이유로 발생하지 않았다고 결론 내리지 않는다.

진단 guard의 최종 상태는 `RESTORED`였고, console printk 설정은 전후 모두 `7 4 1 7`, `ps_trace`는 `N`이었다. KST **03:57:26** 최종 공유기 확인에서 같은 r39 부팅, 진단 OFF, console 복원, 미적용 UCI 변경 없음, LAN2 2.5Gbps·LAN4 carrier, 유선 관리와 HTTPS 200을 확인했다. **03:58:24**에는 Mac의 원래 네트워크 서비스 순서와 Wi-Fi 핫스팟 연결을 복원하고 Wi-Fi 경로의 HTTPS 200을 확인했으며, Wi-Fi 설정 패널에서도 다른 패널로 이동했다.

## 해석과 남은 범위

- 이번 시험은 MacBook의 MLO 다운로드·업로드 경로를 검증했다. Air 실물 절전 복귀 재시험을 수행하지 않았다.
- 0Mbps interval은 없었지만 1초보다 짧은 멈춤까지 배제하지 않는다. 패널 열림 회차의 저하를 기존 Air 멈춤과 동일 원인으로 취급하지 않는다.
- PPE 항목과 TTL 비트는 시험 중 snapshot이다. 전 구간의 가속 유지나 실제 수신 패킷 TTL은 새로 검증하지 않았다.
- 업로드에는 Mac 수신 바이트 기반 저속 자동 진단을 사용하지 않았다. 업로드 sender interval과 receiver 평균의 차이를 유지한다.
- WAN·IPv6·UDP·VLAN/QoS·다중 단말·장기 안정성 및 Tailscale 외부 접속의 모든 경우는 이번 범위에 포함되지 않는다.
- 원본 단말 식별자, 부팅 ID, 설정·백업·원시 로그·로컬 개인 경로는 공개 문서에서 제외했다. JSON의 출처 SHA256은 로컬 근거와 집계의 연결을 보존하며 원본 파일 자체는 공개하지 않는다.
