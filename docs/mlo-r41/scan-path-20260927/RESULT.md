# r41 초기 연결, 동일 설정 전송률의 경로 비교

실제 iperf JSON과 명령에서 스트림당 150Mbps × 4, 합계 목표 600Mbps를 확인했다. 두 회차 모두 연결 나이 상한 20초 전에 시작했는지는 **True**다. TCP 목표 전송률은 순간 상한이 아니며 저하 후 catch-up burst가 600Mbps를 넘을 수 있다.

| 경로 | 시작 연결 나이 초 | 평균 / 최저 Mbps | <500 / 0 표본 | 서버 재전송 | 전송 중 가능한 scan API 겹침 |
|---|---|---|---:|---:|---:|
| hw | 7.385–7.731 | 599.99 / 69.78 | 13 / 0 | 3422 | 33 |
| noft | 8.123–8.967 | 599.97 / 46.21 | 14 / 0 | 3078 | 33 |

[hw 상세](hw/ANALYSIS.json), [noft 상세](noft/ANALYSIS.json)에 native 타이머, PS/BA, 서버 TCP, 경로 증거를 보존했다. noft는 새 데이터 tuple 네 개의 가속 추가만 우회하며 전역 NPU는 켜져 있다. noft의 경로 표본과 기존 규칙 해시 복원을 확인했다.

서로 다른 새 연결의 설정 부하만 일치한다. 순간 송신량·scan 순서·PS 및 RF 조건의 일치를 보장하지 않으며 noft 경로 조회 부하도 남는다. 송신 측 10초 구간 합계는 서버 자체 상대 시계의 반올림된 application Transfer 값이다. API 구간은 RF 체류 시간이 아니고, 누락된 PS 이벤트로 wake 지연을 확정할 수 없다. AP/NPU 전체 무결성이나 원래 Air 문제 해결을 입증하는 결과가 아니다.
