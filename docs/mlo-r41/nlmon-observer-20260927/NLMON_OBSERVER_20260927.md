# r41 관리 통신 관측 경로 확인

기존 커널의 nlmon과 같은 빌드의 tcpdump/libpcap으로 **완전한 nl80211 조회 왕복을 확인했다.** 새 펌웨어를 만들거나 설치하지 않았다. 이는 관측 도구의 동작 확인이며 NR 요청·응답·ACK·Mac의 NR 사용 또는 무선 문제 해결을 입증하지 않는다.

128개 패킷 상한에 도달해 기록은 5.423481초에서 끝났다. tcpdump는 128개 기록, 136개 수신, 커널 drop 0을 보고했으며, snaplen으로 잘린 3개 기록은 통째로 분석에서 제외했다. 잘리지 않은 기록에서 동일 sequence/port의 family 조회 1쌍과 `GET_INTERFACE` → `NEW_INTERFACE` 1쌍을 확인했고 실제 조회 대상 ifindex도 일치했다. **예정한 20초 전체 캡처는 실패했으며 `full_capture_pass=false`를 유지한다.**

첫 시도는 장치에 `stat` 명령이 없어 모듈 로드 직후 중단됐다. 생성된 인터페이스가 없고 모듈 참조가 0인 것을 확인한 후 자체 모듈을 제거했다. 후속 도구는 BusyBox inode 조회와 명령 사전 검사로 보완했다. 두 번째 시도는 상한 종료 후 자체 모듈·인터페이스를 자동 제거했다. 원래 설정 파일 전체 해시, 상태 값을 제외한 nft 규칙, 부팅과 커널 taint가 유지됐고 두 번째 제어기의 유선 확인 8회가 정상이었다. Mac en0 인터넷도 HTTP 200으로 확인했다.

로컬 검사 32개(가드 22, 제어기 5, 분석기 5)는 통과했다. 로컬 검사 통과와 실제 캡처의 시간·길이 제한을 구분한다. 원시 패킷과 장치 식별 정보는 비공개로 보존했다. 수치와 입력 해시는 [NLMON_VERIFICATION_20260927.json](NLMON_VERIFICATION_20260927.json), 복원 결과는 [NLMON_RESTORATION_20260927.json](NLMON_RESTORATION_20260927.json)에 있다.

다음 NR 관측은 관리 프레임을 담을 수 있는 필터와 캡처 예산을 먼저 검증해야 한다. 현재 결과만으로 20초 또는 전체 무선 시험을 빠짐없이 기록할 수 있다고 가정하지 않는다.
