# r41 Neighbor Report 구성 후 초기 전송 관찰

**두 Neighbor Report의 설정·조회는 확인했지만, Mac의 실제 요청·응답 수신·사용은 검증하지 못했다.** 독립 소스 검토에서 `CONFIG_WPA_MSG_MIN_PRIORITY=3`으로 DEBUG/MSGDUMP 메시지가 빌드에서 제외됨을 확인했다. 런타임 MSGDUMP 설정으로는 제외된 메시지를 복구할 수 없으므로, 프레임 로그 부재를 프레임이 없었다는 근거로 쓰지 않는다.

기존 HW 기준 회차와 같은 스트림당 150Mbps × 4, 합계 목표 600Mbps로 비교했다. 두 회차 모두 연결 나이 상한 20초 전에 전송을 시작했고, 회차 안에서 같은 두 MLO 링크 및 네 데이터 흐름의 PPE 등록을 확인했다.

| 회차 | 시작 연결 나이 초 | 평균 / 최저 Mbps | <500 / 0 표본 | 서버 재전송 |
|---|---|---|---:|---:|
| baseline_hw | 7.385–7.731 | 599.99 / 69.78 | 13 / 0 | 3422 |
| nr_hw | 7.455–7.715 | 600.03 / 67.43 | 13 / 0 | 1587 |

Native background 채널 목록은 기준 33회 / 97항목, NR 33회 / 97항목이다. 실제 순서를 비교한 일치 여부는 **True**다. 채널 목록은 요청 기록이고 RF 체류 측정이 아니다. 최초 저하 표본의 연결 나이 범위는 기준 21.392–22.741초, NR 21.460–22.725초다.

전송이 보장되는 구간의 대상 P / gate1 기록은 기준 469 / 118, NR 449 / 112개다. 전역 P/F 누락은 기준 {'P': 111, 'F': 0}, NR {'P': 251, 'F': 0}이며 완전한 절전 지속시간이나 복귀 지연은 계산할 수 없다. 관측 BA 메시지는 각각 21 / 21개로, 프레임 준비/수신 로그 및 MCU 반환 범위이고 전체 전달 성공을 뜻하지 않는다.

NR 제어기 유선 확인 131회(복원 중 7회), 전송 제어기 56회가 정상이었고 NR 설정과 로그 레벨이 복원됐다. 두 집계는 서로 다른 제어기 관측이며 독립 시험 횟수로 합산하지 않는다.

서로 다른 연결이며 NR 회차에는 추가 hostapd 로깅 설정·수집기가 있어 부하가 완전히 같지 않다. TCP 목표율은 순간 상한이 아니므로 회복 시 초과 전송이 가능하다. 서버 TCP 표본은 별도 상대 시계의 반올림된 application Transfer이며 재전송은 무선 손실 개수가 아니다. 이 결과만으로 NR 전달 효과·무효, AP/NPU 전체 원인 또는 원래 Air 절전 복귀 문제의 해결을 확정하지 않는다. 수치·상대 시각·입력 해시는 [분석 수치·입력 해시](https://github.com/VultaV/OpenW1700k/blob/codex/mlo-r30-bridge-offload/docs/mlo-r41/neighbor-report-20260927/NR_CONFIG_20260927.json)에 보존했다.
