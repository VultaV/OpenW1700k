# r40 설치와 Mac 무선 시험

2026-09-27. **r40 설치·부팅은 검증됐고 일반 다운로드는 약 2Gbps를 유지했다. Wi-Fi 설정 화면을 열었을 때의 반복 저하는 남아 있다. RED 수정의 원인 해결이나 Air의 안정성은 입증하지 않았다.**

## 설치·복원

공개 r40 이미지와 장치에 복사한 이미지의 SHA256이 일치했고, 설정·기존 `/root` 파일을 로컬 비공개 백업으로 저장했다. 설정 해시와 `sysupgrade -T` 성공 뒤 설정 보존 설치를 실행했다. 설치 동안 Mac은 iPhone 핫스팟을 사용했다.

새 부팅에서 검증 이미지에 포함된 모듈 74개의 해시, 설정 34개 유지, Tailscale 신원·온라인 상태, AP와 LAN을 포함한 **24 PASS / 0 FAIL / 0 WARN / 0 SKIP, 100%**를 확인했다. `/root`의 기존 파일 1,443개도 설치 후 원래 해시와 일치했다. 커널은 `6.18.44-w1700k-mlo-r32`다. 부팅 로그의 `NPU RED: WM ACK, WA commands queued (host tokens 16384)`는 한 번 관측됐으며 WA readback 증거는 아니다.

Mac은 재부팅 중 DHCP 주소를 놓쳐 잠시 link-local 주소를 사용했다. 직전 관리 주소를 임시 고정해 공유기에 접속한 뒤 원래 DHCP로 복원했고 기존 주소를 다시 받았다. 설치 관찰에서 웹 관리 접속이 없던 구간은 약 3분 20초와 DHCP 복원 중 약 6초다. 이는 Mac에서 본 HTTP 가용성으로, 전체 LAN 물리 단절 시간과 동일하지 않다. 무선 시험은 DHCP 복원 후 시작했다.

## MacBook 시험

MLO 5+6GHz, 2.5Gbps LAN 서버, TCP 4 streams 조건이다. Mac의 유선 관리 연결과 무선 시험 경로를 분리했고, 모든 회차에서 PPE bound fastpath 및 시작·종료 링크 bitmap `0x6`을 확인했다. Wi-Fi 재연결 없이 같은 연결에서 다음 순서로 시험했다.

| 조건 | 시간 | 수신 평균 Mbps | Mac 1초 표본 최저 Mbps | TCP 재전송 | link 2 TXFREE status2 증가 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 설정 화면 닫힘 / 다운로드 | 60초 | 1786 | 55 | 3253 | 750 |
| 설정 화면 열림 / 다운로드 | 60초 | 1437 | 58 | 14861 | 14062 |
| 다시 닫힘 / 다운로드 | 300초 | 1969 | 1843 | 8285 | 323 |
| 닫힘 / 업로드 | 60초 | 1772 | 1428* | 5497 | 0 |

모든 회차의 Mac 1초 합계 표본에 0 구간은 없었다. `*` 업로드 평균은 서버 수신 값이지만 최저·0 구간은 Mac 송신 표본이다. 다운로드는 Mac 수신 표본이다. TXFREE는 전후 합계이며 동일 STA의 중복 출력 세 블록을 한 번만 집계했다. TCP 재전송이나 status2는 무선 손실 패킷 수 및 개별 저하 시점과 일대일 대응하지 않는다.

첫 닫힘 시험의 500Mbps 미만 표본은 시작 4초에 집중됐다. 열림 시험은 12–16초, 28–33초, 45–49초 부근에 반복 저하했으며 500Mbps 미만 표본이 10개였다. 같은 연결에서 화면을 다시 닫은 5분 동안은 최저 1,843Mbps를 유지했다. 네 회차 시험의 유선 HTTP 확인 **571회가 모두 정상**이었다. 시험 무결성·경로 검사 4 PASS는 성능 문제 해결 판정이 아니다.

최신 r39 열림 기준은 평균 1,957Mbps로 정상인 반면, 과거 r39에서는 이미 같은 반복 저하가 관측됐다. 따라서 r40에서 현상이 사라지지 않았음은 확인했으나 RED 변경으로 새로 생긴 회귀라고 확정할 수 없다. Mac `airportd`의 해당 시간 scan/channel 로그 조회는 보존된 일치 기록이 0건이었다. 이것은 스캔이 없었다는 증거가 아니다.

## 종료 상태와 남은 범위

공유기는 r40을 유지한다. 시험 전 UCI 설정, bridge offload와 진단 옵션이 유지됐고 부팅 로그에서 BUG/WARNING/Call trace/timeout/firmware crash 검색 결과는 없었다. Mac은 원래 DHCP·네트워크 순서·iPhone 핫스팟으로 복원했고 핫스팟 인터넷과 유선 관리 접속을 확인했다.

장시간 재연결·reset 복구·다중 단말 자원 경합, WA RED 설정 readback과 NPU token 예산 매핑은 미검증이다. 이 버전은 계속 실험 prerelease이며 일반 안정 버전으로 승격하지 않는다. 후속 판단에는 짧은 정상 속도 재측정보다 화면 열림 때의 단말 가용 시간·링크 절전·송신 대기 및 서버 TCP를 시간상 대응시키는 증거가 필요하다.
