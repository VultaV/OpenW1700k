# W1700K MLO r29 진행 기록

**실험용 수정본입니다. MLO 문제의 완전 해결은 아직 입증되지 않았습니다.**
이 브랜치는 실제 시험한 r29의 드라이버 패치 전체와 hostapd/LuCI/빌드 수정,
회귀 테스트, 공개 가능한 시험 결과를 보존합니다. fastbuild 산출물을 가져온
것이 아니라 OpenWRT-fanboy/OpenW1700k 소스를 로컬에서 빌드했습니다.

- 기준 소스: `6d74443bce54df63f6d877040d406cdbcfc16f81`
- 커널:6.18.44, mt76:`01367e60db433534ad0aa3d3b6c886de8cb7d44c`
- 프로필:Gemtek W1700K UBI2, Tailscale 포함, mt76 패키지 release26
- 새 upstream `10db72e7c6`는 비교만 완료했습니다. 해당 변경 전체를 이 브랜치에
  합치지 않았습니다. 커널/오프로딩 변경과 MLO 수정의 영향을 분리하기 위함입니다.

## 반영한 수정

1. NPU RX 불완전 체인을 보존하고 replacement DMA 주소/메타데이터를 먼저
   기록한 뒤 `dma_wmb()`와 `WRITE_ONCE(ctrl,0)`로 descriptor 소유권을 넘깁니다.
   r29의 신규 수정은0029입니다. 원본/수정/장벽 제거 제어군으로 호스트 모델을
   검사했고 ARM64 `dmb oshst` 생성도 확인했습니다. 실제 장애의 원인 입증과는 별개입니다.
2. AQL 반환 후 절전 TXQ 깨우기, 활성 MLO 링크 PHY 참조,
   두 링크 절전 상태를 반영하는 shared TXQ gate 수정이 포함됩니다.
3. hostapd의 unknown-station 링크 ID 보존, 만료된 PMF MLD 재연결 정리,
   아직 설정되지 않은 링크의 DFS 상태 전달을 수정했습니다.
4. LuCI MLO/ Wi-Fi7 설정 검증·기본값, 이미지 메타데이터 병렬 make 처리,
   Darwin 호스트 헤더 및 libpfring AR 선택을 수정했습니다.
5. 링크별 PS/TX/BA/MCU 진단 패치를 보존합니다. NSTR 실험은 기본값이 비어 있고,
   awake 강제 선택과 상세 추적은 기본 OFF입니다. 이 실험 기능은 해결책으로 켜지 않습니다.
6. overlay CGI는 LuCI 세션/권한 검사와 펌웨어 다운로드 검증을 포함합니다.
   실제 공유기의 개인 설정·비밀번호·Tailscale 상태 파일은 포함하지 않습니다.

패치 SHA256, feed commit, 모듈/펌웨어 해시는 `build-manifest-as-built.json`과
검증 JSON을 참고하세요. 이 manifest의 설치 전 상태 문구는 빌드 당시 기록이며,
현재 설치/시험 상태는 본 문서와 `postinstall_verification.json`이 우선합니다.
호스트 PATH만 공개용으로 일반화했습니다. 무선/NPU 펌웨어11개는 r27과 동일합니다.

## 실제 시험 결과

동일한2.5Gbps 유선 서버, TCP download4streams, 회차당5분.
Air가 주 검증 단말이고 Mac은 회귀 검증 단말입니다. 사용자 정정에 따라
9월19일 전화기 시험은18 Pro, 9월20일 시험은Air로 구분했습니다.
18 Pro는 사용자 요청으로 주 판정에서 제외했습니다. OS/칩셋 원인으로 단정하지 않습니다.

| 단말/조건 | 평균/최저/최고 Mbps | 관찰 |
|---|---|---|
|Mac MLO|1109 /999 /1376|300초,0전송 구간 없음|
|18 Pro MLO(참고)|1105 /0 /1370|측정 도중 멈춤,주 판정 제외|
|Air MLO|1184 /890 /1422|패킷 기록은 중간부터 확보|
|Air MLO|1209 /1124 /1255|전체4흐름300초,ACK 진행 공백>250ms 없음|
|Air MLO,화면 잠금 후|1156 /773 /1411|전체4흐름300초,ACK 진행 공백>250ms 없음|
|Air6GHz 단일 링크|1112 /705 /1212|전체4흐름300초,ACK 진행 공백>250ms 없음|

최근 두 비교 회차의 평균 차이는 MLO+3.96%입니다. 단일 반복과 연결 초기 상태
차이가 있어 성능 우위의 증명은 아닙니다. 잠금 해제의 정확한 시각도 독립 측정하지
않았으므로 unlock 지연 시간 측정으로 해석하지 않습니다.
후기 세 회차는 전체 패킷 수 각각3,868,884 /4,407,508 /4,136,180이고
캡처 커널 드롭0입니다. 유선 점검309/340/181회 모두 통과했습니다.

`tx_failed`에는 재시도 횟수도 더해지며 station statistics는 기본 링크 값을
내보냅니다. MLO의0과 단일 링크 카운터를 손실률로 직접 비교하지 않습니다.
커널 로그와 패킷 시계는 전후 marker로 보정합니다. offset이 변하므로 과거의
association 시각을 정확한 밀리초 기준으로 쓰지 않습니다.

## 실패한 가설과 남은 작업

- 기존 링크 선택0007은 철회했습니다. 강제 awake 선택은 OFF/ON/OFF 시험에서
  평균869/510/838Mbps로 악화되어 기본 OFF를 유지합니다.
- PS 상태와 과거 정체가 함께 나타났지만 이것만으로 firmware 결함을 확정하지 않습니다.
  MCU 성공, 호스트 TX 준비/완료, debugfs 카운터는 실제 무선 전달 증명이 아닙니다.
- 원래의 간헐적 Air 정체를 유발한 조건과 수정 효과의 인과관계는 미확정입니다.
- Air3회 재연결 검증은 중단됐습니다. 새 두 링크 연결 하나는 관찰했으나
  사용자 확인 및3회 절차/최종 전송 시험을 완료한 것으로 세지 않습니다.
- FT/FILS 등 시험하지 않은 hostapd 경로,3링크 MLO,장기간 안정성은 미검증입니다.
- 펌웨어는 버전·해시·동작 경로를 비교했으며 폐쇄형 바이너리 내부의 수정은 하지 않았습니다.

패킷 원본,장치별 주소,설정 백업,인증 자료는 로컬에만 보존했습니다.
빌드와 검증 방법은 [BUILD.md](BUILD.md)를 참고하세요.
