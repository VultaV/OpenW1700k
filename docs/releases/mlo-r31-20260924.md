# MLO r31: 브리지 가속 수정 통합

Gemtek W1700K UBI2용 **시험 릴리스**입니다. r30에서 수정한 브리지 가속 경로와 장비에서 시험한 패키지를 하나의 설치 이미지로 통합했습니다. **r31 이미지 자체는 빌드·추출 검증을 마쳤지만 아직 설치·부팅 시험을 하지 않았습니다.**

## 개선 사항

- CPU를 거치는 LAN→Wi-Fi 브리지 경로의 속도 제한을 줄이기 위한 `bridge-flow-offload 1.0-r2`와 `ip-bridge`를 통합했습니다. 선택한 두 브리지 포트 사이의 IPv4 TCP만 가속하며, 기본값은 비활성화입니다.
- 브리지 통과 패킷의 TTL이 감소하던 문제를 수정했습니다. 소프트웨어 경로와 Airoha PPE가 모두 브리지 TTL을 보존하도록 처리했습니다.
- 브리지 conntrack 참조 처리와 `NF_DROP` 경로의 이중 해제 문제를 수정했습니다.
- 포트를 명시적으로 선택하고 지원하지 않는 토폴로지·정책에서는 가속을 활성화하지 않도록 했습니다. 전역 가속 대신 전용 테이블만 관리합니다.
- r29의 드라이버 수정과 보드별 CPU 배치를 유지했습니다. NPU 펌웨어는 교체하지 않았습니다.

## 확인한 결과

아래 속도는 **설치된 r30 + 대응 패키지**에서 측정했습니다. r31 부팅 시험 결과는 아닙니다.

| 시험 | 결과 |
|---|---|
| 같은 Mac 연결에서 가속 ON / OFF / ON | 평균 1,854 / 1,392 / 1,956Mbps, CPU 4코어 평균 6.76 / 63.36 / 6.89% |
| iPhone Air MLO, 5분 다운로드 | 평균 / 최저 / 최고 1,963 / 1,806 / 2,020Mbps, 사용자 보고상 멈춤 없음 |
| iPhone Air 6GHz 단일 링크 재시험, 5분 | 1,993 / 1,761 / 2,047Mbps, 사용자 보고상 멈춤 없음 |
| Air 절전 이벤트 기록 후속 시험, 5분 | 1,905 / 1,505 / 2,027Mbps, 공유기 중간 구간의 0바이트 기록 없음, 유선 검사 418/418 통과 |
| TTL 비교 | 42개 검사 통과, 패킷 헤더 208,638개에서 TTL64 유지 |

CPU를 거치는 브리지 경로가 주요 속도 제한이었다는 근거입니다. 모든 과거 멈춤의 원인이 해결됐다는 판정은 아닙니다. MLO 트래픽은 주로 6GHz를 사용했으며 두 링크 대역폭이 동시에 합산됐다는 의미도 아닙니다. TTL 검사는 회당 100Mbps·8초의 IPv4 역방향 TCP 범위였습니다.

r31 빌드 9단계가 통과했습니다. 추출 검사에서 커널, 모듈 74개, 펌웨어 11개와 wpad/LuCI 파일 338개가 r30과 동일한 것을 확인했습니다. 커널 ABI는 `6.18.44-w1700k-mlo-r30`입니다.

## 남은 문제와 검증 범위

- 절전 복귀 시험의 일시적 속도 저하와 Air 스트림 하나가 소프트웨어 경로에 남았던 현상의 원인은 아직 확정하지 못했습니다.
- 연결 해제 후 이전 PPE 항목이 남는 현상을 확인했습니다. WCID가 실제로 바뀌는 재연결, 장기간 안정성, 재부팅·방화벽 재시작 후 유지와 Air 업로드 검증이 남아 있습니다.
- 짧은 Mac 시험 중 스캔과 겹친 속도 저하도 기록했습니다. 실패한 속도 검사를 제외해 성공으로 표시하지 않았습니다.
- IPv6·UDP 가속은 현재 활성화 범위 밖입니다. 이후 작성한 재연결 정리 소스 후보는 이 r31 이미지에 포함되지 않습니다.
