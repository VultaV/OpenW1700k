# r34 — MLO 링크 수명 관리·NPU watchdog·업데이트 UI 수정

r33 전체 검토에서 확인한 링크 상태·할당 실패·watchdog 정리 오류와 업데이트 UI 문제를 수정한 **실험 버전**입니다. 전체 빌드와 이미지 검증을 통과했으며, **공유기에 설치하거나 추가 무선 시험을 하지 않았습니다.** Air 절전 복귀의 간헐 멈춤이 해결됐다는 의미는 아닙니다.

## r33 대비 개선

- **MLO 링크 선택자 복구(F02):** 링크 제거·재활성화·추가 실패 뒤 primary/secondary를 실제 활성 링크에 맞춥니다. 살아 있는 primary는 유지하며 교체가 필요할 때 공유 TXQ의 WCID도 갱신합니다. 유효 링크가 0x7로 유지된 채 활성 링크가 0x3→0x6으로 바뀌는 사례도 검사했습니다.
- **WCID 누수 방지(F03):** secondary 링크의 메모리 할당 실패 때 먼저 예약한 WCID를 반환합니다. 반복 실패로 예약 bitmap이 소진되는 경로를 막습니다.
- **NPU watchdog 수명 관리(N01):** 공식 Linux [4bdee806](https://github.com/torvalds/linux/commit/4bdee8060d1e4581624e68fbd369b1afb14df4bc)을 백포트했습니다. work 초기화가 IRQ 등록보다 먼저, IRQ 해제가 work 취소보다 먼저 일어나도록 합니다. 초기 IRQ·probe 실패·제거 경계의 수정이며 정상 운용 중 무선 멈춤의 원인으로 확인된 것은 아닙니다.
- **업데이트 UI 복구·소스 공개(F09/F10):** 호환 이미지가 없을 때의 undefined 접근과 단일 non-factory 이미지 대체 처리 누락을 수정했습니다. 기존 GitHub 업데이트 UI를 고정 LuCI commit용 feed patch와 해시로 공개해 빌드 입력에서 빠지지 않도록 했습니다.
- **빌드 기록 재사용 방지(N02):** 이번 빌드는 이전 성공 JSON을 근거로 단계를 생략하지 않고 9개 make 단계를 모두 실행했습니다.

## 검증

빌드 9단계의 종료코드는 모두 0입니다. 다만 9개 로그 모두 경고가 있으며, 명시한 진단 패턴으로 **반복 포함 1,076줄·정규화한 메시지 309종**을 집계했습니다. 미사용 feed 의존성 14종이 9단계에서 반복됐고, 비어 있는 kmod 경고 28개는 이미지에 설치되지 않은 패키지입니다. 나머지 컴파일러·도구·펌웨어 매핑·W1700K PCI ranges를 포함한 DTC 경고까지 모두 무해하거나 해결됐다고 판단하지 않습니다. 상세와 집계 기준은 `BUILD_WARNINGS.json`에 보존했으며 아래 회귀 검사 수와 구분합니다.

| 검사 | 통과 | 실패 | 경고 | 생략 |
| --- | ---: | ---: | ---: | ---: |
| 실제 mt7996 함수의 링크 수명 관리 | 631 | 0 | 0 | 0 |
| 기존 MLO PS 경로 | 99 | 0 | 0 | 0 |
| NPU 즉시 IRQ·probe 성공/실패 경계 | 90 | 0 | 0 | 0 |
| 추출 이미지의 업데이트 UI | 9 | 0 | 0 | 0 |
| TTL 구조 / 추출 C 가드 | 12 / 2,091 | 0 | 0 | 0 |
| conntrack 소유권 | 7 | 0 | 0 | 0 |
| PPE 소유권 | 11 | 0 | 0 | 0 |
| FDB 정리 | 1,026 | 0 | 0 | 0 |

각 표의 검사 범위 내 통과율은 100%입니다. C 검사는 실제 prepared 함수와 ASan/UBSan을 사용하지만 커널·MCU·하드웨어 서비스는 대체 구현입니다. UI 검사는 RPC/DOM 대체 환경이며 실제 브라우저의 전체 설치 흐름은 미시험입니다. 이 수치를 실기기 안정성 통과율로 해석하지 않습니다.

수정 전 대조에서는 selector 72건, 할당 54건, NPU 2회 실행, UI 3건의 의도한 실패를 확인했습니다. 이 실패는 수정본 통과 수에 합산하지 않았습니다.

이미지를 추출해 FIT 해시·UBI2 장치/호환성·206개 패키지·64개 kmod의 정확한 커널 의존성·74개 모듈의 vermagic을 검사했습니다. **커널 payload와 나머지 72개 모듈은 r33과 바이트 동일**하며 변경된 두 모듈은 이번 빌드의 패키지 payload와도 일치합니다. 기존 전달·TTL 경로는 유지됩니다. 펌웨어 파일 11개와 업데이트 view를 제외한 wpad/LuCI 파일 337개도 같습니다. Tailscale 패키지·부팅 서비스·설정 보존 경로를 확인했고 개인 상태 파일은 이미지에 없습니다.

- mt76 패키지 release: `r27`; NPU 모듈 패키지: `6.18.44-r2`; 업데이트 UI: `26.250.72430~e81743d-r2`
- 이미지: 30,290,793바이트
- SHA256: `ae6861d33660b4e5366af77d369e1fe2920cf14940ee091a1e78e307f28c0e62`

변경된 두 모듈은 공개 인터페이스·공유 구조체를 바꾸지 않아 r32 커널 ABI를 유지합니다. r33 전체 이미지 자체도 부팅 시험을 거치지 않았으며, 바이트 동일성 검사가 그 시험을 대신하지 않습니다. Tailscale 재접속도 실기기 검증 사항입니다. 이번 릴리스는 네이티브 증분 빌드이며 clean-room·bit-for-bit 재현성을 주장하지 않습니다.

## 남은 문제와 새 패치 판단

F01·F05–F08의 권한·설정 UI 문제와 primary 변경 후 큐 재스케줄, RRO/PPE 삭제 실패 경계는 별도 항목으로 남깁니다. Air 절전 복귀 멈춤의 원인도 미확정입니다. 사용자의 요청에 따라 추가 무선 시험은 진행하지 않았습니다.

[9월 26일 전체 검토](https://github.com/VultaV/OpenW1700k/blob/mlo-r34-20260926/docs/mlo-r33/FULL_REVIEW_20260926.md)에 최신 UBI2 `r36602-54e453b074`, 995/996 패치, mt76 PR, NPU 펌웨어·재구현 프로젝트 및 포럼 확인 결과를 기록했습니다. 새 UBI2의 펌웨어 12개는 9월 24일과 동일합니다. 995/996은 순수 L2 TTL·교차 ingress 보호 범위이므로 기존 KEEP_TTL·PPE 소유권·FDB 수정을 대체하지 않습니다. r34는 해당 최신 커널/패치 전체를 교체한 빌드가 아닙니다.

소스·고정 feed patch·재실행 가능한 검증기는 [docs/mlo-r34](https://github.com/VultaV/OpenW1700k/tree/mlo-r34-20260926/docs/mlo-r34)에 있으며, 첨부 `BUILD_RESULT.json`에 실제 검사 수치·해시·한계를 보존했습니다.
