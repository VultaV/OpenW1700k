# r37 — NPU mailbox timeout 뒤 요청 덮어쓰기 방지

NPU 응답이 시간 초과된 뒤 다음 WLAN/PPE 명령이 같은 coherent buffer와 제어 레지스터를 바로 덮어쓰는 경로를 수정했습니다. 이전의 늦은 응답이 새 명령의 성공으로 오인되는 상황을 막기 위해 기존 CTRL3의 WAIT/DONE 상태를 같은 lock 아래 먼저 확인합니다. 사용 중이면 `-EBUSY`, 읽기 실패면 해당 오류를 반환하며 요청·응답 메모리를 보존합니다. 늦은 완료 이후에는 다음 호출이 정상 진행합니다.

추가 대기 루프·상태 필드·vendor firmware 변경 없이 적용했습니다. NPU host package는 `6.18.44-r2`에서 `6.18.44-r3`으로 올렸고 mt76 `r29` 및 r36의 TX publication 수정은 유지했습니다.

## 검증

- 실제 함수·정식 패치를 추출한 ASan/UBSan 검사: 후보 **145 통과 / 0 실패 / 0 건너뜀**. 원본은 79 통과·66 기대 실패였으며, 실패 사유와 늦은 A 응답의 B 성공 오인을 명시적으로 대조했습니다. 부팅·DMA·실기기 시험 수치가 아닙니다.
- 최종 빌드 9단계 종료 코드 모두 0. 첫 시도는 fakeroot의 sandbox 로컬 소켓 제한으로 package 단계에서 중단됐고, 권한을 갖춘 동일 빌드를 재실행했습니다. 빌드 중 재생성된 mt76 소스를 너무 일찍 읽은 사전 검사 1회도 기록·제외하고, 완료 후 모든 소스 검사를 다시 실행했습니다.
- 기존 링크 전환·forward path·WCID·MLO PS·TX/RX ordering·NPU watchdog·TTL·conntrack·PPE·FDB·updater UI 검사 통과. 상세 범위와 수치는 `docs/mlo-r37/BUILD_RESULT.json`에 보존했습니다.
- FIT hash·보드 metadata·APK exact kernel ABI·새 package payload 검사 통과. 이미지에는 206개 package와 74개 module이 있으며 **`airoha_npu.ko`만 변경**됐습니다. kernel·다른 73개 module·firmware 11개·wpad/LuCI 338개 파일은 r36과 동일합니다.
- 전체 시도 로그의 경고 1123회, 고유 메시지 307개를 기록했습니다. 경고가 모두 무해하거나 제거됐다는 뜻은 아닙니다.

## 남은 범위

이 수정은 명령 취소나 NPU 재시작이 아닙니다. 영구 미완료 요청은 계속 busy이며, 상위 stop/reset 실패 처리·공유 IRQ 수명·PPE SRAM 오류 전파는 별도 미해결 항목입니다. 실제 vendor mailbox 선택 명령 대조는 전체 firmware 실행·동시성 검증을 대신하지 않습니다. Air 멈춤의 인과관계도 확정하지 못했습니다.

**장비에 설치하지 않았고 부팅·추가 무선 시험은 수행하지 않았습니다.** 기존 설정 보존이 필요한 실험용 prerelease입니다. 기존 r36 태그·파일을 덮어쓰지 않습니다.
