# r43 — NPU 송신 예산 0 처리 보완

**실험용 prerelease입니다. 9개 빌드 단계, 소스 검사 14그룹, 이미지 검사에 이어 실제 설치·부팅 검사 30 PASS / 0 FAIL / 0 SKIP와 Mac 기본 전송 확인을 완료했습니다. 원래 Air 문제의 해결 판정은 아닙니다.**

설정 34개와 모듈 74개를 대조했고, NPU guard 적용 로그 뒤 version 응답과 실제 네 데이터 연결의 `HW_OFFLOAD`·PPE 등록을 확인했습니다. 다운로드 60초의 평균은 **1,129.152Mbps**(Mac 수신 구간 최저 406.136Mbps), 업로드 20초의 서버 수신 평균은 **1,298.188Mbps**(Mac 송신 구간 최저 1,254.688Mbps)였습니다. 두 회차 모두 1초 전송량 0 구간은 없었고 유선 확인 총 112회가 정상이었습니다. 과거 약 1.9Gbps보다 낮은 처리량이지만 다른 단말의 동시 부하·무선 사용 시간을 통제하지 않아 r43의 개선·회귀로 직접 비교할 수 없습니다. 원래 Air의 간헐적 절전 복귀 멈춤은 미해결 상태입니다. 세부 근거와 관측 한계는 후속 `DEVICE_RESULT.md`·`DEVICE_RESULT.json`에 기록했습니다.

실제 NPU 프로그램에서 ring 여유가 7일 때 송신 consumer에 예산 0이 전달되고, 첫 처리 후 unsigned 감소로 큰 값이 되는 경로를 확인했습니다. 다른 종료 조건이 있어 무한 루프라고 단정하지 않으며, **원래 Air의 간헐적인 절전 복귀 멈춤과의 인과관계는 미확인입니다.**

r43은 정확한 program/data 크기·SHA256 쌍과 원래 명령어가 일치할 때만, 코어 시작 전 program DRAM 복사본의 4바이트를 바꿉니다. 예산 0이면 기존 반환 경로를 사용하며, program 전체 DRAM readback 해시가 다르면 코어 시작 전에 실패합니다. 다른 firmware 쌍은 원래대로 로드합니다. 원본 vendor 파일은 유지하지만 해당 쌍의 실행용 DRAM 프로그램은 의도적으로 달라집니다.

- `kmod-airoha-npu` release r3 → r4, 커널/모듈 ABI `6.18.44-w1700k-mlo-r32` 유지입니다. 이미지에서 `airoha_npu.ko`만 변경됐습니다. 커널·DTB·나머지 73개 모듈·원본 firmware 11개·wpad/LuCI 338파일은 r42와 동일합니다.
- 최종 prepared 소스 검사 14그룹은 14 PASS / 0 FAIL / 0 SKIP입니다. 실제 loader 함수 추출 후보 24건과 원본 대조 1건을 포함하며 MMIO 등은 fixture입니다. 이미지에 포함된 업데이트 UI 검사도 9 PASS / 0 FAIL / 0 SKIP입니다.
- 별도 RV32 제한 실행 검사는 정상 band 0·1의 양수 입력 131,082건과 예산 0 입력 2건을 확인했습니다. 전체 펌웨어 실행·동시성·실제 DMA 동작의 증명은 아닙니다.

부팅 경로 전용이며 실행 중 재적재의 안전성을 제공하지 않습니다. 이번 설치에서 새 부팅의 NPU version 응답과 기록된 실제 흐름의 가속 등록을 확인했지만, 모든 패킷·NPU 실행 경로의 정상 동작까지 증명하지는 않습니다. Mac 결과로 Air 문제 해결을 판정하지 않습니다. 적용 조건·검사·동시성 한계는 [r43 설명](https://github.com/VultaV/OpenW1700k/blob/mlo-r43-20260927/docs/mlo-r43/README.md)에 있습니다.

기존 공개 자산 8개는 검증된 이미지, `SHA256SUMS`, `BUILD_RESULT.json`, `BUILD_WARNINGS.json`, `SOURCE_CHANGE_PROOF.json`, `build-manifest.json`, `GUARD_FRESH_VERIFICATION.json`, `README.md`입니다. 이 원본 자산과 소스 태그는 그대로 유지하고, 후속 `DEVICE_RESULT.md`·`DEVICE_RESULT.json` 두 자산을 추가했습니다. 기존 빌드 기록과 README는 설치 전 시점의 기록을 보존합니다. 원시 장비 로그·패킷·설정 백업·개인 식별 정보는 포함하지 않습니다.

빌드 경고는 408회·서로 다른 문구 154개로 검사 통과 수와 분리해 기록했습니다. r42 대비 새 7개 문구는 이 이미지에 설치되지 않은 coova-chilli/iptables 라이브러리의 libtool 패키징 경고입니다. 모든 경고를 무해하다고 판정한 것은 아닙니다. 최초 fakeroot 샌드박스 실패와 watchdog 역패치 문맥 검사 중단도 `BUILD_RESULT.json`에 보존했습니다. watchdog 검사기는 임시 입력의 헤더 문맥만 정리하며 실제 함수와 기존 오류 대조를 유지합니다.
