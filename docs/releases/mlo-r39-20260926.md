# r39 — NPU 가속 전송의 BA 세션 갱신 누락 수정

상대가 0이 아닌 ADDBA timeout을 협상했을 때, NPU 가속 트래픽의 전송 상태 보고가 계속 들어와도 mac80211 집계 세션의 활동 시각이 갱신되지 않던 조건부 결함을 수정했습니다. 기존 WED 전용 refresh 조건에 NPU를 추가했습니다. timeout 협상·실제 무전송 만료·station/TID 검사와 기존 처리 경로는 유지합니다.

기존 Air r32 실패 기록에서도 host 송신 준비 카운터 변화 없이 수용된 TXS 카운터가 1,571개·2,246개 증가한 구간을 확인했습니다. 관련 코드 경로가 실제 실행된 근거입니다. **Air의 협상 timeout·정확한 멈춤 시각은 없어, BA 만료가 당시 원인이었거나 이 수정으로 멈춤이 해결됐다고 확정하지 않습니다.**

## 검증

- 원본: 16 PASS / 2 FAIL. NPU-only PPDU·MPDU 보고에도 잘못된 유휴 종료가 발생한 두 경우입니다.
- 정확한 음성 대조: 16 PASS / 2 EXPECTED_FAIL, 예상 외 실패 0. 임의 오류나 crash는 기대 실패로 인정하지 않습니다.
- 수정 후보와 최종 prepared source: **18 PASS / 0 FAIL / 0 WARN / 0 SKIP, 100%**. ASan/UBSan 진단 없음. 실제 dispatcher·refresh·협상 대입·timer 콜백을 추출한 동기식 host 검사이며 kernel concurrency나 hardware 시험은 아닙니다.
- 정식 패치 fuzz 0 적용 결과와 최종 prepared `mac.c`의 byte/hash 일치. 최종 빌드 9단계 종료 코드 모두 0. 기존 회귀 검사를 포함한 12개 소스 검사 프로그램과 이미지 updater UI 검사 통과.
- FIT·보드 metadata·package payload·exact kernel ABI 검증 통과. 206개 package, 74개 module 중 **`mt7996e.ko`만 변경**. kernel·다른 73개 module·firmware 11개·wpad/LuCI 338개 파일은 r38과 같습니다.
- mt76 package r29→r30. Ethernet `6.18.44-r2`, NPU `6.18.44-r3` 유지. 빌드 경고 386회·고유 149개를 별도 기록했으며 경고의 무해성이나 전체 CVE 감사 통과를 뜻하지 않습니다.

## 범위와 남은 문제

PID 0으로 거부되는 TXS, 보고 자체가 없는 정체, timeout보다 긴 보고 간격은 이 수정이 해결하지 못합니다. TXS 활동을 ACK 성공으로 취급하지 않습니다. NPU stop/reset·IRQ 수명·RRO 오류 처리, runtime PPE 삭제 실패, 권한·설정 UI 문제도 남아 있습니다.

vendor NPU의 0 예산 문제는 별도 조사로 유지했습니다. caller 상수를 바꾸는 대안은 정상 slow 처리까지 바꾸므로 채택하지 않았습니다. 같은 band의 이번 미게시 descriptor를 기다리는 순환 교착 가설은 정상 단일 producer 조건에서 배제했으며, 하드웨어 metadata 계약과 실제 정체 인과는 미확정입니다. firmware 바이너리를 변경하지 않았습니다.

상세 근거와 기존 Air 기록 대조는 `docs/mlo-r39/REVIEW.md`에 있습니다. **공유기 설치·부팅·추가 무선 시험은 수행하지 않았습니다.** 실험용 prerelease이며 기존 r38 태그·펌웨어를 변경하지 않습니다.
