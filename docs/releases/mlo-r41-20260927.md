# r41 — 링크 활성화 실패 후 멈춘 TXQ 재등록

**실험용 prerelease. 빌드·이미지·설치·부팅 및 Mac 비교 시험 완료. 새 연결 초반 저하는 남아 있습니다.**

새 MLO 링크 활성화 중 드라이버 오류가 발생하면, 임시 링크 마스크 때문에 스케줄 목록에서 빠진 공유 송신 큐가 기존 마스크 복원 뒤에도 멈춰 있을 수 있습니다. r41은 mac80211의 실패 경로에서 마스크 복원과 링크 정리가 끝난 뒤, 데이터가 남은 TXQ를 다시 등록하고 드라이버에 알립니다. 원래 오류 반환값과 PS·AQL 검사, 재설정 중 wake 보류 동작은 유지합니다.

이 수정은 조건부 실패 복구입니다. 최근 Mac 새 연결 초반 저하나 기존 Air 절전 복귀 멈춤을 해결했다고 판정하지 않습니다. r40에서 도입한 RED 실험의 효과도 이 변경으로 입증되지 않습니다.

## 완료한 오프라인 검사

- 실제 mac80211 core 함수와 mt7996/mt76 함수를 추출한 회귀 검사: 원본 **39개 assertion 충족**, 후보 **39개 assertion 충족**, 양쪽 예상 밖 실패 **0개**. 기존 24개 검사에 core 경로 15개를 추가했습니다.
- 원본 검사는 오류 후 마스크 복원과 AQL 반환에도 backlog **10개가 미등록 상태로 남는 정확한 음성 대조**를 포함합니다. 원본 제품 동작이 정상이라는 뜻이 아닙니다. 후보에서는 같은 10개를 실제 추출 scheduler가 처리합니다.
- active-mask filtering, 오류값·기존 링크·PS 상태 보존, 성공·early exit, null/empty/fragment TXQ, 재설정 중 DIRTY 처리와 잠금 조건을 확인했습니다. ASan·UBSan 정상입니다.
- 활성 목록·잠금·RCU·할당·hash/debugfs는 host fixture입니다. 실제 동시 실행, RCU grace period, DMA 수명이나 장비 성능은 이 검사 범위가 아닙니다.

공식 Linux [`fd179f8a05be`의 활성화 함수](https://github.com/torvalds/linux/blob/fd179f8a05be3ccae366b9b96e176b51fbe54aab/net/mac80211/sta_info.c)는 로컬 원본과 동일했습니다. 해당 revision의 함수 비교이며 모든 상위 대기 패치에 대한 결론은 아닙니다.

## 빌드 검증

9단계 빌드와 13개 소스 검사, 설치 이미지 UI 9개 검사가 통과했습니다. 실제 prepared 소스 두 변형을 원본+패치와 대조하고 정확한 역방향 복원도 확인했습니다.

mac80211 package release는 **2 → 3**, 변경 모듈은 **`mac80211.ko` 하나**입니다. 나머지 73개 모듈, 커널 payload, 11개 펌웨어와 338개 wpad/LuCI 파일은 r40과 같습니다. kernel release는 `6.18.44-w1700k-mlo-r32`이며 kernel package ABI도 r40과 같습니다.

빌드 경고는 **383회·147종**이며 r40과 같은 정규화 문구입니다. 새 문구와 수정 파일 직접 경고는 0개지만 기존 경고가 무해함을 입증한 것은 아닙니다. 경고 원문 분류는 BUILD_WARNINGS.json에 기록했습니다.

펌웨어 크기: **30,290,792 bytes**. SHA256: `092788281aae270fb8dcd5e85d8a4ed16ad433bdfc75105028bdc29d9b0eca6f`.

## 설치·실기기 검증

설치 후 24개 검사가 통과했고 설정 34개·Tailscale·모듈 74개 해시를 확인했습니다. Mac 60초 MLO 시험은 새 연결 평균 1730.97Mbps / 최저 70.49Mbps, 안정 후 평균 1923.28Mbps / 최저 1774.38Mbps였고 두 회차 모두 0Mbps 구간은 없었습니다. 새 연결 첫 5초의 저하는 남아 있습니다. 유선 확인 154회 정상, 시험 후 핫스팟 복원 완료입니다.

한 차례 순차 비교이며 r41의 성능 개선이나 Air 멈춤 해결 증거로 해석하지 않습니다. 실패 활성화 분기는 장비에서 강제 주입하지 않았습니다. BUILD_RESULT.json은 설치 전 빌드 시점 기록이며, 추가 검증은 [설치·Mac 시험 결과](https://github.com/VultaV/OpenW1700k/releases/download/mlo-r41-20260927/DEVICE_TESTS_20260927.md)에 분리했습니다.

## 연결 후 스캔 시점의 추가 비교

같은 Mac에서 iperf를 더 일찍 시작하자 MLO와 6GHz 단일 링크 모두 초반 약 1.9Gbps 전송 후, 연결 나이 약 22초에 첫 500Mbps 미만 구간이 나타났습니다. macOS의 연결 후 20초 BEST CONNECTED 스캔 요청·절전 상태·재전송 증가가 함께 관측됐습니다. BA 준비는 전송 전에 끝나 있었으며, 이번 현상을 MLO 두 링크만의 문제로 한정할 수 없습니다. 공통 NPU/PPE·Wi-Fi 펌웨어 경로의 영향과 원래 Air 절전 복귀 멈춤은 미확정입니다.

40초 평균/최저는 MLO 1241/66Mbps, 단일 6GHz 1383/133Mbps입니다. 두 회차 모두 0Mbps 구간은 없었고, 일시 저하가 포함된 순차 시험이므로 모드별 우열이나 수정 효과로 해석하지 않습니다. 유선 확인과 설정·진단 옵션·핫스팟 복원을 검증했습니다. 신규 제품 수정·펌웨어·태그 변경은 없습니다. [상세 비교 및 관측 한계](https://github.com/VultaV/OpenW1700k/releases/download/mlo-r41-20260927/ASSOCIATION_COMPARISON_20260927.md).
