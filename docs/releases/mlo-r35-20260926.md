# r35 — MLO 링크 전환 뒤 TXQ 복구·가속 경로 조회 수정

r34의 두 드라이버 후속 문제를 수정한 **실험 버전**입니다. **공유기에 설치하거나 추가 무선 시험을 하지 않았습니다.** Air 절전 복귀의 간헐 멈춤이 해결됐다는 의미는 아닙니다.

## r34 대비 개선

- **성공한 MLO 링크 변경 뒤 TXQ 재등록:** mac80211이 먼저 링크 mask를 바꾸는 동안 이전 primary의 절전 상태 때문에 스케줄에서 빠진 공유 TXQ를 새 활성 primary 선택 후 다시 등록합니다. 기존 PS/AQL 판단과 완료 경로는 유지합니다. 실패한 activation의 callback 이후 rollback은 해결 범위 밖입니다.
- **가속 경로의 링크 조회 일치:** primary ID를 한 번 읽어 VIF BSS와 station WCID 조회에 같이 사용하고, 비활성 MLO 링크와 확인된 selector 변경은 거부합니다. RCU 아래 호출되는 경로에서 mutex를 전제한 helper 대신 RCU로 VIF 링크를 조회합니다. 비MLO 및 embedded link 0 동작은 유지합니다.
- **NPU 바이너리 근거 보완:** 실제 vendor blob의 디코딩 807행·raw anchor 3곳을 바이트 대조했습니다. Clanker E2/E3의 구조·버전 차이, 실제 pool 할당·반환, RRO action 3 범위를 기록했습니다. 새 NPU/MT7996 펌웨어 바이너리는 넣지 않았습니다.

## 검증

9개 make 단계를 모두 실행했고 종료코드는 모두 0입니다. 반복 포함 경고 **387줄·정규화 메시지 149종**이 있습니다. r34와 공통 148종, 신규 1종이며 신규는 xtables-addons의 System.map 부재로 depmod를 생략한 경고입니다. `BUILD_WARNINGS.json`에 설정 선택·실제 설치 여부와 집계 한계를 기록했습니다. 증분 빌드에서 미관측된 경고를 해결된 것으로 세지 않으며 모든 경고가 무해하다는 판정도 아닙니다.

검사 범위 내 통과율은 각각 100%입니다. 실제 prepared 함수와 ASan/UBSan을 사용하되 kernel·RCU·MCU·하드웨어·scheduler는 대체 구현입니다. 실제 kernel 동시성·공정성·부팅·무선 안정성의 통과율이 아닙니다. UI 검사도 실제 설치 흐름을 실행하지 않습니다.

음성 대조에서는 수정 전 링크 전환 4건, forward path 24건, RCU 보완 전 후보 2건의 의도한 실패를 확인했습니다. NPU watchdog의 수정 전 실행 2회와 바이너리 검사기의 잘못된 입력 4건도 예상대로 거부됐습니다. 이 수치는 후보 통과 수에 합산하지 않습니다.

추출 이미지의 FIT·UBI2 메타데이터, 206개 패키지, 64개 kmod의 정확한 kernel 의존성, 74개 모듈의 vermagic을 검사했습니다. **커널 payload와 73개 모듈은 r34와 바이트 동일하며, 변경 모듈은 mt7996e.ko 하나입니다.** 새 모듈은 이번 빌드의 package payload와도 일치합니다. 펌웨어 11개와 wpad/LuCI 파일 338개도 동일합니다. Tailscale 패키지·서비스·상태 보존 경로를 확인했고 개인 상태 파일은 이미지에 없습니다.

## 미해결 항목과 새 공개 패치

[전체 후속 검토](https://github.com/VultaV/OpenW1700k/blob/mlo-r35-20260926/docs/mlo-r35/REVIEW.md)에 권한·설정 UI F01/F05–F08, 실패한 activation rollback, RRO 삭제 반환값 무시, 기존 PPE binding 무효화 및 SRAM clear 실패 경계를 기록했습니다. 최종 확인 뒤 링크 변경·selector ABA·PPE 게시까지 원자성을 제공하는 수정은 아닙니다. **Air 간헐 멈춤의 원인·해결은 미확정입니다.**

[9월 26일 upstream 조사](https://github.com/VultaV/OpenW1700k/blob/mlo-r35-20260926/docs/mlo-r33/FULL_REVIEW_20260926.md)의 최신 일반 UBI2는 `r36602-54e453b074`·kernel 6.18.52이며 펌웨어 12개는 직전 일반 빌드와 같았습니다. 995/996은 순수 L2 TTL·교차 ingress 보호로 기존 KEEP_TTL·PPE 소유권·FDB 수정을 통째로 대체하지 않습니다. r35는 최신 tree 전체 교체가 아닙니다. 일부 포럼은 접근 실패로 최신 본문을 확보하지 못했습니다.

[NPU 후속 대조](https://github.com/VultaV/OpenW1700k/blob/mlo-r35-20260926/docs/mlo-r34/FIRMWARE_FOLLOWUP_20260926.md)는 Clanker errata를 현재 blob의 확인된 결함으로 귀속할 근거가 부족함을 기록합니다. CPU가 낮거나 PPE가 유지된다는 이유만으로 NPU 문제를 배제하지 않습니다.

소스·manifest·재실행 가능한 검증기는 [docs/mlo-r35](https://github.com/VultaV/OpenW1700k/tree/mlo-r35-20260926/docs/mlo-r35)에 있으며 첨부 `BUILD_RESULT.json`에 실제 명령·해시·검사 결과를 보존했습니다.
