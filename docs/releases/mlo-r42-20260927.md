# r42 — MLO 절전 전이 기록 보강

r41 Mac 시험에서 전송 저하와 스캔·절전 전이의 시간 관계를 확인했지만, 선택 가능한 P 전이 로그가 제한에 걸려 일부 누락됐습니다. r42는 선택적 `ps_trace`의 P 기록 한도만 5초당 128건에서 1,024건으로 늘립니다. 기본 OFF, F 이벤트 한도, 두 링크 MLO 조건과 순번·출력 형식은 유지합니다. **속도나 절전 복귀를 고쳤다는 릴리스가 아닌 진단판입니다.**

- mt76 패키지 release 31 → 32. 실제 모듈 변경은 `mt7996e.ko` 한 개입니다.
- 9단계 빌드 성공, 기존 소스 검사 13개 그룹 PASS / 0 FAIL / 0 SKIP, 설치 이미지 UI 검사 9 PASS / 0 FAIL / 0 SKIP입니다. 각각 통과율 100%이며 실기기 합격률이 아닙니다.
- 이미지의 74개 모듈·ABI를 검사했습니다. 커널과 나머지 73개 모듈, 펌웨어 11개, wpad/LuCI 파일 338개는 r41과 같습니다.
- 빌드 경고는 383회, 정규화한 문구 147개입니다. 검사 성공과 구분하여 `BUILD_WARNINGS.json`에 기록했습니다.
- 커널/모듈 ABI: `6.18.44-w1700k-mlo-r32`, mt76 소스 `01367e60`. NPU/MT7996 바이너리 펌웨어는 변경하지 않았습니다.

기존 PS 알림·길이 검사와 스캔 복귀 관련 공식 수정은 이미 포함되어 있습니다. 현재 확인한 소스·패치 범위에서는 이번 Mac 증상을 직접 해결하는 새 수정은 찾지 못했습니다. P 로그가 완전해져도 worker 실행, 실제 무선 채널 복귀나 펌웨어 버퍼 상태를 증명하지 못합니다. 기록 자체의 부하와 유한한 한도도 남습니다.

빌드 기록 파일은 설치 전 상태를 보존합니다. 이후 r42 설치·새 부팅 검증은 **24 PASS / 0 FAIL / 0 SKIP**로 완료됐습니다. 설정 34개, 모듈 74개, Tailscale의 기존 식별 상태가 유지됐고 5/6GHz AP·LAN2 2.5Gbps·Mac 유선 관리 연결이 복구됐습니다. 설치 중 유선 HTTP의 마지막 정상 표본과 첫 복구 표본 사이는 약 172초였으며, 물리 링크 단절 시간을 뜻하지는 않습니다.

Mac 새 MLO 연결의 40초 진단 시험(총 600Mbps 목표)은 평균 **599.99Mbps**, 최저 **57.56Mbps**, 500Mbps 미만 14구간·0Mbps 0구간이었습니다. 데이터 4개 연결의 PPE 등록, 같은 두 링크(0x6), 유선 HTTP 55회 정상을 확인했습니다. 전역 P 1,450건의 내부 순번 누락은 0이며, 전송 중 대상 P 652건을 확보했습니다. 자세한 수치·관측 한계는 `ANALYSIS.json`과 `RESULT.md`에 있습니다.

추가로 PS/BA 진단 로그를 끈 90초 최대 속도 시험은 평균 **1,618.73Mbps**, 최저 **111.15Mbps**, 0Mbps 구간 0개였습니다. 초반 저하 뒤 마지막 30초는 평균 **1,961.90Mbps**, 최저 **1,919.49Mbps**, 최고 **2,009.65Mbps**였고 유선 확인 110회가 모두 정상이었습니다. 이 별도 시험에는 native 스캔/PS 시간 기록이 없어 동일 원인이라는 인과 판정을 내리지는 않습니다. `NORMAL_90S.json`에 전체 구간을 남겼습니다.

완전한 P 기록에서 저하 구간의 **77.263–83.475%**가 host PS 조건상 두 링크 절전 시간과 겹쳤습니다. 마지막 조건 해제와 저하 종료 시각의 오차 범위가 겹쳐 **해제 뒤 수초 정체는 입증되지 않았습니다**. 가속 경로는 이 host TXQ 조건을 패킷마다 실행하지 않으므로, 위 비율을 NPU의 실제 패킷 차단 시간으로 해석할 수 없습니다. 자세한 근거는 `WAKE_TIMING.md/json`에 기록했습니다.

이번 결과는 초반 저하를 재현한 진단 결과입니다. Mac 시험 결과로 원래 Air의 간헐적 절전 복귀 멈춤이 해결됐다고 판정하지 않습니다.

이미지 SHA256: `a1f28cdeb3bc1498e6e9c2b2948ff93a2738dab16b28c88c73388f09c59cb93b`.

모든 시험 후 설정 34개·진단 OFF·유선 관리를 재확인했고 Mac은 기존 핫스팟으로 복원했습니다. 원시 단말 식별자·패킷·설정 백업은 공개하지 않았습니다.

9월 27일 서버 TCP 동시 기록을 추가했습니다. 이 회차는 **Mac Wi-Fi 설정 패널을 열어 둔 조건**으로, 이전 General 패널 시험과의 대조군으로 쓰지 않습니다. 600Mbps 목표·40초에서 평균 481.47Mbps, 최저 38.80Mbps를 기록했습니다. 캡처 361,503개·drop 0이며 네 연결의 동시 ACK 공백은 최장 354.583ms였습니다. 서버 CPU 평균 2.13%, CPU 제한 증가 0, 데이터 흐름의 수신 윈도우 0 ACK는 0개였습니다. host PS 조건 해제 뒤 수초 정체는 이번에도 입증되지 않았고, 서버 시계를 공유기와 직접 맞추지 않았으므로 정확한 wake 지연으로 환산하지 않았습니다. `ENDPOINT_RESULT.md`와 `ENDPOINT_DATA.json`에 결과와 조건 차이를 보존했습니다.

새 공개 UBI2 `ubi2_2026.09.27_r36617-2af23e846e`도 확인했습니다. 직전 트리와 실제 39개 파일이 달라졌으나 mt76·Airoha·hostapd·firmware 레시피 변경은 없습니다. 새 libpcap 1.10.7·tcpdump 4.99.7은 r42에 아직 적용하지 않았습니다. 이 릴리스는 계속 커널 6.18.44의 별도 수정본이며 새 공개 이미지와 동일하다고 표시하지 않습니다. 세부 참조는 `UPSTREAM_REFRESH.md/json`에 있습니다. 기존 r42 태그와 펌웨어는 변경하지 않았습니다.
