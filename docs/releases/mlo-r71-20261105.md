# r71 — NPU RX 링 반환 순서 수정·실기 검증

**빌드·설치·시험을 완료한 실험용 prerelease입니다. 2.4GHz 포함 MLO의 성능 저하는 남아 있으며, 전체 안정성 해결판이 아닙니다.** 정상 재시험으로 앞선 실패 결과를 대체하지 않았습니다.

## 수정 사항

- upstream [mt76 PR1169](https://github.com/openwrt/mt76/pull/1169)의 커밋 `105e1b13a25c874fd7d750d28cd06ab05a778921`에서 빠져 있던 RX 공개 순서 수정을 적용했습니다. dequeue에서 즉시 포인터를 반환하던 처리를 옮겨, 새 버퍼를 보충한 뒤 `(head+1)%ndesc`를 공개합니다. 기존 다중 슬롯·descriptor·TX 배리어 수정은 유지합니다. 병합 완료된 upstream 수정이라는 뜻은 아닙니다.
- mt76 패키지 r43. 커널/모듈 공통 ABI는 `6.18.59-w1700k-mlo-r70`입니다. r70 가속 정리 수정, 원본 NPU 0.8/package 0.8-r3, 16MiB coherent pool, 기존 QDMA, wpad9 및 Wi-Fi 펌웨어 6개를 유지합니다. 새 바이너리 바이트 패치는 없습니다. 다른 ABI의 모듈을 혼용하지 마세요.

## 검증 결과

- 실제 fill/dequeue 함수의 호스트 50개 사례 통과, 이전 코드 실패 재현, 잘못된 포인터 대조 실패를 확인했습니다. 기존 RX/TX 4개 그룹과 배리어 대조도 준비된 실제 소스에서 통과했습니다.
- 전체 빌드 472.5초·종료 0. 이미지의 UBI2/FIT·payload·공통 ABI·모듈/펌웨어 해시·비공개 상태 미포함을 확인했습니다. 기존 U-Boot 빈 패키지 정리의 무시된 경고는 별도로 기록했습니다.
- 실제 설치 후 SSH 복귀 102.6초. 설정·SSH·Tailscale 노드 식별자가 유지됐고, 장치의 모듈/펌웨어 해시가 이미지와 일치했습니다.
- 기본 5+6GHz: 초기 다운로드 1970 / 업로드 1793Mbps. 5분 연결 유휴 후 다운로드 3분 평균 1955 / 업로드 1분 평균 1827Mbps, 0Mbps 구간 없음. 전체 OS 잠자기 시험은 아닙니다.
- 동일 TCP 100Mbps 연결에서 가속 ON/OFF/ON 시 PPE 바인딩 2→0→2, 0Mbps 구간 없음. 32MiB 무선 SSH 왕복 해시 일치. 브리지 가속 OFF 상태의 300Mbps·45초 업로드 통과. 이때도 NPU 펌웨어는 동작합니다.

## 남은 문제와 대조시험

Mac의 실제 무선 인터페이스에 고정한 4-stream TCP 시험입니다. 서버 LAN2는 2.5Gbps, 별도 유선 관리 LAN4는 1Gbps입니다. 각 방향 60초이며, AP와 단말 링크를 확인했습니다.

| MLO 조합 | 최초 다운로드 / 업로드 Mbps | 재시험 다운로드 / 업로드 Mbps |
|---|---:|---:|
| 2.4+5GHz | 1596 / 1773 | — |
| 2.4+6GHz | 16 / 78 | 1695 / 107 |
| 2.4+5+6GHz | 63 / 229 | 1904 / 1519 |
| 5+6GHz | 1936 / 1781 | — |

최초 2.4+6GHz 다운로드에 0Mbps 구간 3회가 있었습니다. 최초 대기는 무선 전원을 켠 뒤 40초였으므로 실제 연결 시점과의 차이가 있습니다. 재시험은 드라이버가 보고한 연결 시간 60초 이상·안정된 링크/peer 상태를 확인했지만 2.4+6GHz 업로드 저하는 남았습니다. 따라서 대기 부족만으로 설명되지 않으며, 같은 조합이 항상 실패한다는 뜻도 아닙니다.

`mlo_best_link` Y/N/Y 대조에서는 다운로드 1920 / 511 / 1946Mbps, 0Mbps 구간 0 / 22 / 0회였습니다. OFF는 안전한 우회책으로 확인되지 않아 기본값 Y로 복원했습니다. OFF는 odd-TID 경로와 주기적 선택도 함께 바꾸므로 순수한 단일 변수 원인 증명은 아닙니다.

심한 저속 구간의 약 10초 단위 공유기 CPU 사용률은 코어별 5% 미만이었습니다. 지속적인 공유기 CPU 포화 근거는 없으나 짧은 순간 부하·단말·무선/NPU 정지는 제외할 수 없습니다. 이전 r70의 per-peer TX 정지 원인도 아직 확정하지 못했습니다.

## NPU 분석 범위·최종 상태

원본 NPU 0.8의 네이티브 HOST RX 생산자는 `(P+2)%512`의 24B descriptor DONE를 검사하며, 확인한 소프트웨어 경로에서는 consumer CSR을 읽지 않습니다. 따라서 호스트 50개 사례의 하드웨어 limit 가정이 실제 펌웨어 계약과 동등하다고 증명된 것은 아닙니다. CSR의 하드웨어 credit/IRQ 동작은 미확정입니다. `FIRMWARE_CONTRACT_REVIEW.md`에 경계를 기록했습니다.

원래 무선·네트워크·가속 설정 해시 일치, UCI 미적용 변경 없음, 2.4GHz 단독 AP와 5+6GHz MLD 및 기본 모듈 파라미터 복원을 확인했습니다. SSH/Tailscale·유선 서버·무선 DNS/TLS/WAN 검사가 통과했습니다. 승인된 설치 재부팅 외 유선 관측 4293회와 WAN/Proxmox 각 859회에서 실패가 없었습니다. 감시를 한 차례 중단·재개했으므로 관측 공백까지 무중단을 증명하지는 않습니다. 모든 시험 프로세스와 복원 가드는 종료됐습니다.

실제 약전계 전환·전체 OS 잠자기·야간 안정성·모든 DMA 타이밍/동시성은 미검증입니다. 설정 백업·MAC·원시 패킷·인증 정보는 공개하지 않았습니다. 상세 실패·재시험·복원 기록은 추가 첨부한 `DEVICE_REPORT.md`, `DEVICE_TESTS.json`, `DEVICE_SHA256SUMS`를 확인하세요. 최초 빌드 첨부물은 빌드 당시 기록으로 보존합니다.
