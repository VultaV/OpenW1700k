# r71 — NPU RX 버퍼 보충 후 링 반환

현재 코드에 빠져 있던 upstream PR1169의 RX 공개 순서 수정을 적용합니다. NAPI가 소비한 버퍼를 스택에 넘긴 뒤 새 버퍼를 보충하기 전에 하드웨어 포인터를 반환하던 동작을 고칩니다. 이제 보충 완료 후 `(head+1)%ndesc`를 공개합니다. 기존 다중 슬롯·DONE 읽기·메모리 배리어 수정은 유지합니다.

- 실제 fill/dequeue 함수의50개 호스트 사례에서 이전 실패·수정 후 통과를 확인했습니다. 잘못된 포인터 변조는 실패하고 기존 RX/TX4개 그룹·배리어 대조도 통과했습니다.
- 초기화·NAPI·복구 호출을 검토했습니다. 실제 NPU 소유권·DMA 타이밍·초기 전체 할당 실패의 진행성·r70 송신 정지의 원인성은 아직 미확정입니다.
- mt76r43. 커널/공통 모듈 ABI `6.18.59-w1700k-mlo-r70`와 r70 가속 정리 수정, 원본 NPU0.8/package0.8-r3·Wi-Fi 펌웨어6개·wpad9를 유지합니다. 구형/신형 모듈 혼용은 금지합니다.

전체 빌드와 이미지 검증이 완료됐습니다. 빌드·설치·부팅·실기 결과를 별도로 추가하며, 실험용 prerelease입니다. r70에서 재현된 잔여 MLO 정지가 해결됐다고 선행 주장하지 않습니다. 실제 약전계·전체 OS 잠자기·야간 안정성은 미검증입니다.

빌드472.5초, 종료0. 이미지 SHA256 `5b256cbc0ba7e325b4f1ba4ae69af42bb1732f188c7638fb096411252fe4a4a7`. 실제 이미지의mt76core변경·원본NPU·Wi-Fi6개·UBI2/FIT·공통ABI70·비공개 상태 미포함을 검증했습니다. 커널/DTB와NPU·Ethernet·nf_flow_table모듈은r70과 일치합니다. 이 빌드 기록 시점에는 설치·부팅 미실행이며, 실기 결과를 별도 기록합니다.

추가 바이너리 검토: 원본NPU0.8의 네이티브 HOST RX 생산자는 `(P+2)%512`의24B descriptor DONE를 검사하며, 확인한 소프트웨어 경로에서 consumer CSR을 읽지 않습니다. 따라서50개 호스트 사례의 하드웨어 limit 가정은 실제 펌웨어 계약과 동등함을 증명하지 않습니다. CSR의하드웨어 credit/IRQ 동작은 미확정이며, 수정이 무효라고 입증된 것도 아닙니다. FIRMWARE_CONTRACT_REVIEW에 이 경계와 실기 검증 필요성을 기록했습니다.
