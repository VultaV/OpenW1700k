# MLO r32: 재연결 흐름 정리와 PPE 슬롯 보호

Gemtek W1700K UBI2용 **시험 릴리스**입니다. 단말 재연결 시 이전 가속 항목이 남거나 새 무선 목적지가 이전 규칙으로 덮어써질 수 있는 경로를 수정했습니다. **r32는 설치·부팅·실기기 성능 검증 전입니다.**

## r31 대비 개선

- mac80211 단말 제거 이벤트를 통해 해당 단말의 이전 브리지 흐름을 기존 netfilter GC로 정리합니다. 동일 네트워크 공간·출력 포트·목적지와 이벤트 이전 세대만 대상으로 합니다.
- 공통 흐름 teardown을 한 번만 수행해, 이전 흐름의 반복 정리가 같은 conntrack에 새로 등록된 흐름의 상태를 지우지 않도록 했습니다.
- Airoha PPE가 동일 tuple의 규칙을 여러 개 덮어쓰던 경로를 수정했습니다. 최신 등록 규칙 하나를 선택하고 이전 슬롯 연결을 정리합니다.
- 하드웨어 슬롯 재사용·해시 충돌 시 다른 흐름을 삭제하지 않도록 확인합니다. L2 하위 흐름의 데이터와 목록 연결도 보존해 삭제·통계 경로에 같은 검사를 적용합니다.
- r31의 브리지 TTL 보존과 선택한 포트 쌍의 IPv4 TCP 가속을 유지합니다. NPU/무선 펌웨어는 교체하지 않았고 새 설치의 가속 기본값은 비활성화입니다.

## 검증

- PPE 실제 코드 추출 검사: **11 통과 / 0 실패**. 기존 소스에서 같은 검사 중 10개 실패를 재현했고, 충돌 대조 검사 1개는 기존 소스도 통과했습니다. ASan/UBSan을 사용하지만 하드웨어 동작은 모형입니다.
- netfilter 검사: 매칭 13개, 거부 이벤트 9개, 삽입 실패 1개, 게시/이벤트 교차 실행 1,000개, teardown 3개 통과.
- 대상 ARM64 객체와 전체 커널·모듈을 빌드했습니다. 빌드 9단계가 최종 통과했습니다. 최초 패키징은 로컬 `fakeroot` 소켓의 샌드박스 차단으로 실패했고 일반 권한으로 재실행했습니다.
- 추출 이미지의 FIT 해시, 보드·UBI2 메타데이터, 모듈 74개의 r32 ABI, 패키지 206개, 펌웨어 11개 유지, wpad/LuCI 파일 338개 유지와 개인 Tailscale 상태 미포함을 확인했습니다.

이 검사는 과거 Air 멈춤의 해결이나 r32 처리량을 증명하지 않습니다. 약 2Gbps의 앞선 결과는 r30에서 측정한 것이며 r32 속도 결과로 재사용하지 않았습니다.

## 남은 확인과 설치 범위

실제 WCID가 바뀌는 재연결, 이전 HW 등록/삭제 순서, 다른 단말 유지, 유선 연속성, Air 업로드·절전·장기간 안정성이 남아 있습니다. 정리는 비동기이며 메모리 할당이나 SRAM 접근 실패에 대한 완전한 복구까지 검증한 것은 아닙니다. VLAN·IPv6·UDP 가속 확대와 NPU 펌웨어 교체는 포함하지 않았습니다.

커널 릴리스는 **`6.18.44-w1700k-mlo-r32`**입니다. 흐름 구조체가 바뀌므로 r30/r31 또는 다른 빌드의 모듈을 혼용하지 마세요. 공개와 공유기 설치는 별개이며 현재 장비에는 이 이미지를 설치하지 않았습니다.
