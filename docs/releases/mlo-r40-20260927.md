# r40 — MT7996 NPU 경로 RED 초기화 실험

기존 r39는 RED에 WA disable만 전송했습니다. r40은 MT7996와 활성 Airoha NPU 조합에서 MediaTek의 non-WED offload 초기화 순서(WM 제어 → WA enable → WA token config)를 적용합니다. host 토큰 예산을 사용하고 다른 chip/offload 경로는 유지합니다. 런타임 토글이나 새로운 펌웨어 blob은 추가하지 않았습니다.

WM 응답 확인과 WA 명령 전송 성공은 실제 RED 설정 readback을 뜻하지 않습니다. 공식 패치의 Airoha 호환성·Air 멈춤 해결은 미확정이므로 **실험 prerelease**입니다. r39로 복귀하려면 기존 이미지를 재설치해야 합니다.

## 빌드 검증

- 9개 make 단계와 실제 prepared source 검사 13개 프로그램 통과. 새 RED 검사는 50 PASS / 0 FAIL / 0 SKIP, ASan·UBSan 정상. 기준 r39는 legacy·오류 32 PASS와 예상된 RED 계약 부재 1건입니다.
- 완성 이미지 검증 통과: `mt7996e.ko`만 변경. kernel, 나머지 73개 모듈, firmware 파일 11개, wpad/LuCI 파일 338개는 r39와 동일합니다.
- package 206개, 모듈 74개. mt76 package r31, Ethernet r2, NPU r3. kernel release `6.18.44-w1700k-mlo-r32`, kernel package ABI `6.18.44~73da9a4281bd33ef609e81ecc0cb78e7-r1` 유지.
- 빌드 경고 383회·147종을 별도 보존했습니다. r39 대비 새 정규화 경고 문구 0개이며, 누락 dependency 관련 활성/설치 package와 빈 kmod의 설치 건수는 각각 0입니다. 경고를 PASS로 계산하지 않습니다.
- 이미지 SHA256: `fb4d3d433d38be7888062b2a8111295f305f60e47ea938d61b0b8b11d687f85b`.

## 실제 시험 상태

2026-09-27 후속: r40 설치·부팅 검사 24 PASS / 0 FAIL, 설정·Tailscale 보존과 모듈 74개 일치를 확인했습니다. 기존 `/root` 파일 1,443개도 복원됐습니다. 설치 때 Mac DHCP 주소가 늦게 돌아와 임시 관리 IP로 접속한 뒤 기존 DHCP를 복원했습니다.

Mac MLO 다운로드는 설정 화면을 닫은 5분 동안 평균 **1,969Mbps·최저 1,843Mbps**였고, 업로드 60초 평균은 **1,772Mbps**였습니다. 네 회차 시험 중 유선 HTTP 확인 571회는 모두 정상이었습니다.

**설정 화면을 연 60초는 평균 1,437Mbps·최저 58Mbps로 반복 저하가 남았습니다.** RED로 현상이 해결됐다고 판정하지 않습니다. 과거 r39에서도 같은 패턴이 있었으므로 새 회귀인지도 미확정입니다. r40은 실험 prerelease를 유지합니다. [설치·시험 세부 기록](https://github.com/VultaV/OpenW1700k/blob/codex/mlo-r30-bridge-offload/docs/mlo-r40/DEVICE_TESTS_20260927.md)

첨부 BUILD_RESULT는 설치 전 빌드 시점의 불변 기록이며, 설치·시험 결과는 별도 DEVICE_VALIDATION 기록으로 제공됩니다.

변경 전 r39의 새 Mac 60초 기준은 설정 화면 닫힘 평균 1,824Mbps(첫 2초 저하), 열림 평균 1,957Mbps·최저 1,857Mbps였습니다. 두 회차 모두 0Mbps 표본은 없었고, 이전 반복 저하가 이번 열림 시험에서는 재현되지 않았습니다. r40 이후 정상 성능만으로 원인 해결을 주장하지 않습니다.

[검토·공식 소스 근거](https://github.com/VultaV/OpenW1700k/blob/codex/mlo-r30-bridge-offload/docs/mlo-r40/REVIEW.md) · [빌드 절차](https://github.com/VultaV/OpenW1700k/blob/codex/mlo-r30-bridge-offload/docs/mlo-r40/BUILD.md)

설명 문서 첨부는 `DEVICE_TESTS_20260927_CORRECTED.md`를 참조하세요. 이전 설명의 “이미지와 모듈 해시”는 “검증 이미지에 포함된 모듈 해시”로 정정했습니다. 부팅 후 전체 flash readback을 검증했다는 뜻이 아닙니다. 기존 첨부는 보존했습니다.

## 9월 27일 절전·TCP 후속

같은 MLO 연결에서 설정 화면 열림 60초는 평균 **1239Mbps·최저 45Mbps**, 닫힘 60초는 **1959Mbps·최저 1820Mbps**였다. 유선 HTTP 154회는 모두 정상이었다. 열림의 반복 저하와 host PS 변화, 서버 TCP 혼잡 윈도 감소가 함께 관측됐다. PS 방출 제한에 따른 누락이 있어 실제 wake 시각과 AP 내부 지연은 확정하지 못했다. 이 기록은 원인 해결 판정이 아니다.

상위 소스의 새 13파일은 빌드 도구·mtd·다른 장치 지원 변경이며 새 PS/RED/EMLSR 수정은 없었다. [PS·TCP 및 상위 갱신 기록](https://github.com/VultaV/OpenW1700k/blob/codex/mlo-r30-bridge-offload/docs/mlo-r40/PS_CAUSAL_20260927.md)과 새 `PS_CAUSAL_20260927.md/json` 첨부를 제공한다. 기존 r40 이미지·태그·첨부는 보존한다.
