# r38 — PPE SRAM 초기화 실패를 성공으로 처리하는 문제 수정

PPE SRAM 초기화 반복문의 내부 `err`가 반환할 오류값을 가려, commit 실패 뒤에도 성공으로 초기화를 계속하던 문제를 수정했습니다. 내부 선언을 제거해 첫 오류를 기존 PPE·Ethernet probe 정리 경로로 전달합니다. 0개·정상 완료 동작은 유지하고 오류 뒤 다음 항목을 처리하지 않습니다.

실제 SRAM 초기화에 실패하면 Ethernet probe도 실패합니다. 이 시점은 NAPI 시작·포트 등록·TX/RX DMA 활성화 전이며 기존 오류 정리 경로를 검토했습니다. 이미 가동 중인 Air의 간헐 멈춤 원인으로 연결된 증거는 없습니다.

공식 Linux [d7d81b003013](https://github.com/torvalds/linux/commit/d7d81b00301398fcd38cf5b5869f0fdb674472ef)이 2026년 6월 이미 같은 문제를 수정했지만 기존 6.19 백포트에는 반영되지 않았습니다. r38은 내부 선언 제거 방식으로 같은 오류 전파를 복원했으며 공식 v2의 즉시 반환 방식도 별도 원본 복사본에서 16개 검사를 통과했습니다. 정확한 cherry-pick이나 오늘 공개된 새 패치로 표시하지 않습니다.

## 검증

- 실제 추출 함수를 사용하는 PPE 검사 **16 PASS / 0 FAIL / 0 WARN / 0 SKIP, 100%**. 기존 11건과 새 5건을 포함합니다. 원본은 13 PASS와 false-success 기대 실패 3건이며, 임의 오류·crash를 기대 실패로 인정하지 않았습니다. ASan/UBSan 진단은 없었습니다.
- 정식 패치 fuzz 0 적용 결과·검사 후보·최종 prepared C 파일의 바이트와 해시가 일치했습니다. 최종 빌드 9단계 종료 코드는 모두 0입니다.
- 기존 mailbox 145건과 TX/RX·링크 전환·forward path·WCID·MLO PS·watchdog·TTL·conntrack·FDB·updater UI 검사도 통과했습니다. 범위별 원문 결과를 `docs/mlo-r38/BUILD_RESULT.json`에 보존했습니다.
- FIT·보드 metadata·exact kernel ABI·설치 package payload 검증 통과. 206개 package, 74개 module 중 **`airoha-eth.ko`만 변경**됐습니다. kernel·다른 73개 module·firmware 11개·wpad/LuCI 338개 파일은 r37과 동일합니다.
- Ethernet package `6.18.44-r1` → `6.18.44-r2`; NPU `6.18.44-r3`, mt76 `r29` 유지. 전체 로그 경고 1074회·고유 308개는 별도 기록했으며 무해 판정이나 전체 CVE 감사가 아닙니다.

## NPU 후속 조사와 남은 문제

기존 Air 실패 로그에 SER 실행 흔적은 없었지만, 전용 trace 부재로 발생 자체를 완전히 배제하지 못했습니다. 실제 vendor NPU의 작업 루프 정지 확인과 하드웨어 큐 배출은 별도 단계이고, 호스트 timeout은 firmware 취소나 전체 DMA 정지를 뜻하지 않습니다. 단순 return·자동 full reset을 안전한 복구로 추가하지 않았습니다.

NPU stop/reset·공유 IRQ 수명·RRO 오류 처리, runtime PPE SRAM 삭제 실패 및 설정 UI·권한 문제는 남아 있습니다. Air 실제 실패와 전체 TCP·동시 NPU 상태를 함께 갖춘 기존 기록도 확보하지 못했습니다. 상세 근거는 `docs/mlo-r38/REVIEW.md`에 기록했습니다.

**장비에 설치하지 않았으며 부팅·추가 무선 시험은 수행하지 않았습니다.** 실험용 prerelease이고 기존 r37 태그·이미지는 변경하지 않았습니다. vendor firmware 바이너리도 수정하지 않았습니다.
