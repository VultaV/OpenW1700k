# r66 — NPU 메모리 범위 보장과 QDMA 처리 정리 (실험 버전)

**초기 실기기 검사 중 LAN2 쪽 서버·Proxmox 접근 불가를 관찰해 시험을 중단하고 r65 복원을 완료했습니다. 복원 후 두 서버가 다시 응답했습니다. 원인은 아직 분리되지 않았으며 r66을 안정화 버전으로 사용하지 마세요.**


r65의 DFS 라디오 범위 제한·160MHz 대피 수정은 유지하고, NPU의 coherent DMA를 접근 가능한 DRAM 범위 안에 두도록 수정했습니다. WLAN용16MiB 풀을 예약하고 기존 메일박스·mt76 NPU 버퍼가 그 풀을 사용하도록 연결합니다. 일반 패킷의 streaming DMA는 유지합니다.

QDMA는 송신·NAPI·정리 경로의 불필요한 하드 IRQ 차단과 미사용 카운터를 제거해 기존 BH 잠금으로 되돌렸습니다. 소스 포트/RX IRQ 보정과 메일박스 재시도는 유지합니다.

- 참고: OpenWrt PR25928의23d295c6(반영 시 미병합), 커뮤니티 e0da9590bb.
- 커널/모듈 ABI: `6.18.59-w1700k-mlo-r66`. 큐 구조체 변경에 따라 r65와 모듈을 섞을 수 없습니다. 브리지 가속 패키지 r6의 검증 목록도 갱신했습니다.
- NPU 펌웨어0.8, mt76 r40, hostapd/wpad r9는 유지합니다. 구형 TX-budget 바이트 가드는 이 펌웨어에 적용되지 않습니다.
- 호스트 검사: 실제 풀 연결/정리 코드7개, 기존 메일박스145개, 브리지 가속22개 통과. 실제 이미지의 DTB 풀·phandle·ramoops 보존과 부팅 후 메모리 주소는 별도 검증합니다.
- 설치·부팅·속도 시험 결과는 준비되는 대로 후속 기록에 추가합니다. 빌드·이미지 검증은 완료됐으며, 이 배포 시점에는 r66 설치·부팅을 아직 시험하지 않았습니다. 후속 실기기 결과는 별도 기록합니다.

r65에서 관찰한 초기 TCP5초 정지와 일부 흐름 저하의 원인이라는 증거는 아직 없습니다. 두 드라이버 변경을 함께 적용했으므로 성능 차이가 생겨도 한 변경의 효과로 단정할 수 없습니다. 실험용 prerelease이며, 야간 장기 안정성·전체 OS잠자기·실제 약전계 전환은 미검증입니다.

빌드911.1초, 이미지 SHA256: `e2338a015a0ec7ac2f54edac76fa1aa0bcf6d0c248d2079535774e0a4bfafb02`. FIT 구성·UBI2 레이아웃·모듈 ABI·NPU 풀 DTB·비공개 상태 미포함 검사 통과. 기존 DFS 회귀22개 및 hostapd 대피13개도 통과했습니다.

실기기 초기 결과는 `DEVICE_TESTS.json`에 보존했습니다. 새 풀의 주소·메일박스는 확인했으나 실제 내부망 시험은 통과하지 못했으므로 r66은 사용 권장하지 않습니다. 다음 r67에서 QDMA 변경을 제외해 분리 검증합니다.
