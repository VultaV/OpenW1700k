# r65 — MLO DFS에서 즉시 사용 가능한 대피 채널 우선

r64에서 다른 대역으로 레이더 감지가 전파되는 결함은 수정됐지만, 160MHz 대피 때 AP 재시작으로 연속 27초의 0Mbps가 재현됐습니다. r65는 즉시 사용할 수 있는 80/40MHz 채널을 CAC가 필요한 넓은 채널보다 먼저 선택해 기존 링크별 CSA 경로를 사용하도록 바꿉니다.

DFS/NOP 규제 검사는 그대로 사용합니다. 즉시 사용할 채널이 없으면 기존 CAC 절차를 따르며, ETSI uniform spreading과 일반 AP 동작은 유지합니다. 커널·mt76·NPU 바이트는 r64와 같습니다.

빌드 성공(356.7초), 이미지 SHA256: `f96a2516380a983e63646a3d0c05d76209d27299b20ba360817a858d9debcdff`. FIT 구성·UBI2 레이아웃·포함 패키지·바이트 무결성 검사를 통과했습니다. 커널/DTB/mt76 모듈은 r64와 바이트가 같습니다. 비공개 런타임 상태가 이미지에 없는 것을 확인했습니다.

## 빌드 및 검증

- 실제 hostapd 선택 C: 수정 전 13개 중 3개 실패 → 수정 후 13개 통과; non-BE 10개, DFS dispatcher 216개 통과. ASan/UBSan 검사.
- 커널/모듈 ABI: `6.18.59-w1700k-mlo-r32`. mt76 r40, hostapd/wpad r9, NPU 0.8 시험 펌웨어.
- 설치 전/후 상태와 실기기 결과는 아래 후속 기록에 추가합니다. 빌드 시점에는 r65의 설치·부팅·DFS 복구가 검증되지 않았습니다.

## 제한

실험용 prerelease입니다. 긴 시간의 무선 안정성, 실제 약전계 전환, NPU 0.8의 모든 경로는 검증되지 않았습니다. FIT는 해시 검증을 수행하지만 신뢰된 키의 서명이 있는 이미지는 아닙니다. 설정 유지 업그레이드가 필요하며 설치 중 유선·Tailscale이 일시 중단됩니다.
