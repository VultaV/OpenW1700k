# r49 — 오류 처리·상태 파일 보강

**실험용 prerelease입니다. 2026-10-10 실제 장치에 설치해 유선·무선·LuCI를 확인했습니다.** r48의 커널
6.18.55를 그대로 두고 드라이버·사용자 영역의 오류 처리와 LuCI 보드 앱의 root 상태 파일 쓰기를 고쳤습니다.
커널 ABI \`6.18.55-w1700k-mlo-r32\`, 모듈 74개, 무선·NPU 펌웨어, 패키지 목록은 r48과 같습니다. MLO 간헐
멈춤의 해결 여부는 바뀌지 않았습니다.

## 바뀐 것

- airoha: MT7531 netlink PHY 읽기·쓰기 오류를 성공으로 보고하던 것을 netlink 오류로 돌려줍니다. NPU BA
  예약 메모리 명령도 다른 명령과 같은 재시도 도우미를 거칩니다(일시 오류로 WLAN NPU 초기화가 중단되지 않음).
- mt76(\`kmod-mt76\` r34): txpower SKU 갱신이 실패하면 캐시를 되돌려 재시도되게 하고, NPU RX 디스크립터의
  프레임 수가 큐보다 많으면 rate-limit 로그를 남깁니다.
- w1700k-wifi-watchdog 2: 상태·잠금을 \`/var/run\`에 둡니다.
- LuCI 보드 앱: FlowSense·jitter 데몬·airtime 상태를 mktemp+rename으로 쓰고, NPU PLL 쓰기 실패를 보고하며,
  wifi7의 OWE 프로필 저장과 "Collect logs"(이전에는 빈 결과를 Done으로 표시)를 고쳤습니다. 팬 프리셋 미리보기
  갱신, netspeedtest 결과 링크 정규식 고정.

## 검증

- r48에서 설정 유지 설치, \`sysupgrade -T\` "Signature check OK", 유선 HTTP 감시 기준 약 100초 중단 뒤 복구.
  설정·Tailscale 상태 보존, NPU 예산 가드 적용, 세 라디오와 MLO 두 링크(5·6 GHz 160 MHz), 브리지 오프로드,
  커널 경고 없음, 워치독 상태는 \`/var/run\`.
- Safari에서 LuCI 주요 화면 렌더링 확인. WiFi 7 "Collect logs"가 dmesg·logread가 든 파일을 내려받고,
  팬 프리셋 미리보기가 바로 바뀝니다.
- Mac 무선(iperf3 4흐름 30초, AWDL 켜짐): MLO 5+6 하향 1,216·1,993·1,984 Mbps, 상향 1,812·1,804 Mbps.
  단일 5 GHz·6 GHz도 오프로드 포트를 맞추면 1.97–1.99 Gbps. 3링크(2.4+5+6) MLO는 AP는 정상이지만 Mac이
  2.4 GHz로 접속하면 158 Mbps에 머물러 권장하지 않습니다. 유선 lan4(1GbE)↔lan2 844/932 Mbps, WAN 815/818 Mbps.
  상세와 구성별 표는 [r49 기록](../mlo-r49/README.md)에 있습니다.

## 알려진 제약

- \`bridge-flow-offload\`는 설정에 적은 두 포트(\`lan2\`, \`ap-mld0\`)에만 적용됩니다. MLO를 끄면 Wi-Fi netdev
  이름이 바뀌어 오프로드가 내려가므로 포트를 다시 지정해야 합니다.
- 이 드라이버의 MLO 구성에서는 5·6 GHz 채널 스캔을 할 수 없습니다.
- r48 이전 이미지로 되돌리면 커널 모듈도 함께 바뀝니다. 다른 커널용 kmod를 섞어 설치하지 마세요.
