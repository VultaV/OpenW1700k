# r56 — hostapd upstream 2026-10-21

r55 위에서 hostapd를 OpenWrt upstream main(2026-10-21)으로, uhttpd를 2026-10-19로 맞춘 버전입니다. 커널, mt76,
mac80211, ucode, 무선·NPU 펌웨어는 r55와 같습니다. 2026-10-22 실제 장치에 설치해 확인했습니다. MLO 간헐 멈춤의
해결 여부는 바뀌지 않았습니다.

## 바뀐 점

- hostapd: 패치 세트가 hostap 제출본으로 다시 정리됐고, AP MLD 첫 링크 재시작 시 nl80211 BSS 유지, 공유 인증자의
  한 번 초기화와 새 첫 링크로의 이동, 링크별 EAP 모드, 드라이버가 중단한 스캔 재시도, 빈 링크 ID 할당, 시작하지 않은
  링크를 요청하는 ML 연결 거부 등이 들어왔습니다. 포크 패치 `9999-deliver-dfs-state-to-unconfigured-links`는 1줄
  오프셋으로 그대로 적용되고 `test_hostapd_dfs_pending_link.py`가 통과합니다.
- uhttpd 2026-10-19: 새 ucode의 `STATUS_BREAK`를 스스로 처리하고 ubus list 요청 인자를 검증합니다. r55의 포크
  uhttpd 패치는 뺐습니다. rpcd 패치는 유지합니다.

## 실기기 확인 (2026-10-22)

| 항목 | 결과 |
|---|---|
| 설치 | r55에서 설정 유지, `sysupgrade -T` "Signature check OK", 약 95초 만에 접속 |
| 부팅 | 커널 경고 0, NPU 버전 0.1111, MLO 5 GHz·6 GHz 160 MHz, 송신 출력 23/18/23 dBm, 오프로드 정상 |
| LuCI | 로그인 화면, `/ubus` 세션 RPC 응답 |
| Mac 재부팅 직후(iperf3 4흐름 20초) | 하향 1,849·1,998 Mbps, 상향 1,801 Mbps, 절전 전환 0 |
| 재연결 8회 A/B(같은 날 같은 조건) | r56: 맥이 8회 모두 6 GHz에 연결, 15초 하향 482~1,126 Mbps. r55: 6 GHz 4회(662~1,006), 5 GHz 4회(553~790) |

- 이 날은 맥 쪽 상태 때문에 두 펌웨어 모두 10/19 수준보다 낮았습니다. 다운로드 중 맥이 초당 약 17회 절전 상태를
  오갔고, AWDL·스캔·실시간 세션·iPad 연결·신호 세기로는 설명되지 않았습니다. 맥을 재부팅하면 절전 전환이 0이 되고
  2 Gbps로 돌아왔으며, 재연결을 반복한 뒤 다시 떨어졌습니다. 같은 조건의 A/B에서 r56이 r55보다 나쁘다는 근거는
  없었습니다.
- 재연결 시 맥이 5 GHz 링크를 주 링크로 잡은 경우는 r55에서 8회 중 4회, r56에서 0회였습니다. 표본이 작아 단정하지
  않습니다.
