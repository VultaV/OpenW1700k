# r43 동일 연결의 정상·저하 비교 — 2026-09-27

**같은 r43 부팅과 MLO 연결에서 약 1.14Gbps·정체가 있던 회차 이후 약 1.96Gbps의 정상 회차를 관측했다. 새 펌웨어나 설정 변경으로 해결한 결과는 아니다. 원래 Air의 절전 복귀 멈춤도 해결 판정하지 않는다.**

Mac을 무선 클라이언트로, 유선 2.5Gbps Linux 서버를 대상으로 사용했다. 모두 TCP 다운로드 4 streams·무제한 속도이며, 유선 관리 연결을 유지했다. 세 회차의 association 시작값과 전후 부팅·설정 해시가 같았다. 회차 사이 시간과 진단 부하가 다르므로 통제된 ON/OFF 인과 실험은 아니다.

| 회차 | 시간 | 평균 / 최저 / 최고 Mbps | 1초 전송량 0 | 유선 확인 |
|---|---:|---:|---:|---:|
| 앞선 진단 OFF | 60초 | 1135.767 / 0 / 1405.117 | 1 | 77/77 정상 |
| PS·BA 및 native 로그 | 60초 | 1962.077 / 1883.746 / 1997.526 | 0 | 78/78 정상 |
| 진단 복원 후 | 20초 | 1918.906 / 1795.898 / 1955.276 | 0 | 34/34 정상 |

이번 60초 서버 캡처는 회전 파일 3개, 1,684,407 records이며 수신 수와 일치하고 kernel drop은 0이었다. 실제 네 데이터 흐름의 SYN·sequence 범위·종료를 검증했다. 각 흐름의 ACK 공백은 최대 약 38.7–41.3ms였고, 네 흐름 공통 100ms 초과 무ACK 구간은 0개였다. 앞선 저하 회차의 공통 공백 108개·최대 1,209.444ms와 다르다. ACK 공백과 누적 ACK 진행 공백은 서로 다른 지표다.

서버와 Mac의 전후 시각 응답 20개, Mac과 공유기의 전후 표본 10개를 대조했다. 합성 시각 범위의 폭은 약 19.189ms이며, 실제 60초 패킷 창 전체가 커널 기록 안에 포함된다. 커널 기록 255개, 전역 PS 이벤트 208개의 내부 순번 누락은 0이었다. 대상 단말 PS 상태 변화 40개를 연결해 검증했으며, 전송 창 안에서 host 송신 gate가 닫혀 있던 시간의 계산 범위는 0–0ms였다. 이는 기록된 host 상태이며 실제 RF 체류시간이나 NPU의 패킷 차단 여부를 직접 측정한 것은 아니다.

전송 중 macOS 위치 서비스의 2.4GHz 검색 요청도 관측됐다. 해당 구간에도 약 1.96–1.97Gbps가 유지됐으므로 검색 요청의 존재 자체를 정체 원인으로 판단할 수 없다. 이전 저하 회차에는 AWDL의 36/149 채널 일정이 기록됐지만 이번 native 기록에서 새 일정 갱신이 없어 실제 일정 차이를 비교할 수 없다. 이전 자료는 사후 `log show`, 이번 자료는 실시간 `log stream`으로 수집 범위도 다르다. AWDL OFF 시험은 수행하지 않았다.

이번 서버 iperf CPU 평균은 한 코어 기준 6.405%, 컨테이너 CPU는 7.707%이며 throttle 증가가 없었다. 공유기 전체 CPU 평균은 6.758%였다. 네 흐름의 하드웨어 가속 등록도 확인했다. 이것만으로 모든 NPU 내부 실행 경로가 정상임을 증명하지 않는다.

PS/BA·TX 진단은 종료 후 모두 OFF, 기존 PS gate 수정은 ON으로 확인했다. 부팅·네트워크·무선·방화벽·bridge offload 설정은 유지됐다. 마지막 20초 시험은 서버 패킷·PS 동시 기록을 하지 않은 짧은 후속 확인이며, 정상 속도가 진단을 계속 켜 놓아야만 유지되는 상태는 아니었다.

후속 과제는 저하 상태에서도 이번과 같은 시각 정렬 PS/TCP 기록을 확보하는 것이다. r43의 NPU 예산 0 가드 실행 빈도나 실제 DMA 지연은 아직 측정되지 않았다. 정상 회차가 있다고 앞선 실패를 취소하거나, AWDL·NPU 어느 한쪽을 원인에서 배제하지 않는다. 원시 패킷·주소·장치 식별자·설정은 공개하지 않는다.
