# r42 — 새 MLO 연결의 업로드·서버 패킷 비교

2026-09-27. **업로드에서도 연결 직후 저하가 재현됐다.** 전송 중 마지막 두 링크 절전 조건 해제 뒤에는 서버의 연속 수신과 누적 ACK가 18.374ms 이내에 확실하게 진행됐으며, 마지막 시험 데이터 수신까지 100ms 이상 진행 공백은 없었다. 이번 Mac 현상을 AP의 대용량 하향 데이터 처리에만 한정할 수 없다. 업로드의 ACK도 하향 경로를 거치므로 AP·펌웨어를 원인에서 제외하는 결과는 아니다.

원래 Air의 간헐적 절전 복귀 멈춤은 별개로 남는다. 이번 시험은 최대 속도나 Air 수락 시험이 아니며 펌웨어·라우터 설정을 변경하지 않았다.

## 조건과 결과

r42, 같은 Mac, 같은 위치의 새 5+6GHz MLO 연결에서 4개 TCP 흐름을 각각 150Mbps 목표를 설정해 40초 전송했다. System Settings는 시작 전부터 종료까지 General 패널이었다. 시험 종료와 시각 측정이 끝난 뒤에만 Wi-Fi 패널을 열어 기존 핫스팟으로 복원했다.

|---|---:|---:|
| 서버 수신 평균 / Mac 수신 평균 | 599.964Mbps | 599.963Mbps |
| Mac 송신 / 수신 1초 구간 최저 | 70.357Mbps | 62.669Mbps |

| 유선 관리 확인 | 56회 정상 | 55회 정상 |

업로드의 Mac socket 송신 구간과 다운로드의 Mac 수신 구간은 관측 지점이 다르다. 각 회차에서 스캔 수와 절전 시간이 달랐으므로, 최저 속도나 회복 지연의 크기를 정밀한 방향별 대조군으로 비교하지 않는다. 두 방향에 비슷한 초기 저하가 있다는 범위의 관측이다.

이번 업로드의 첫 서버 데이터 수신은 연결 후 7.493–7.514초였다. Mac의 BEST CONNECTED 스캔 요청은 연결 후 20.270–20.291초에 기록됐다. Wi-Fi 설정 패널에서 발생한 스캔 요청은 없었다. 4개 데이터 흐름의 PPE 등록과 동일 MLO 두 링크(0x6)를 전후 확인했다.

## 서버·시계·절전 기록

- 서버에서 회전 파일 2개, 1,142,181개 패킷을 확보했다. 필터 수신 수와 일치하고 커널 drop은 0이다. 원시 순서의 최대 약 2.15μs 역전 7개를 기록한 뒤 시각순으로 분석했다.
- 흐름별 초기 iperf cookie의 37 sequence bytes를 제외했다. 각 흐름의 unique 수신·최종 연속 수신·누적 ACK·iperf 송수신이 모두 **750,125,056 bytes**로 일치했다. FIN 뒤 ACK 1바이트는 실제 FIN을 확인한 경우에만 정규화했다.
- 서버에서 송신한 수신 윈도우 0 ACK는 0개였다. 서버 CPU는 한 코어를 100%로 할 때 평균 5.02%, 최대 표본 14.79%였으며 CPU quota 제한·throttle 증가는 없었다. 1초 표본이 순간적인 호스트/IRQ 부하까지 배제하지는 않는다.
- 서버–Mac 20회, Mac–공유기 10회 시각 비교를 사용했다. 결합 오차 폭 **18.334ms**를 보존했으며 iperf 시작 시각을 추정 기준으로 대체하지 않았다.
- 전역 P 기록 880건의 내부 순번 누락은 0이다. 대상 단말의 상태 전이 738건을 검사했다. 전송 중 마지막 두 링크 절전 조건 해제는 첫 서버 데이터 수신 후 30.408–30.427초에 있었다. 다음 관측된 조건 설정은 시험 데이터 종료 뒤였다.
- 해제 뒤 네 흐름 모두 **18.365ms 안에 확실한 연속 수신 진행**, **18.374ms 안에 확실한 누적 ACK 진행**이 있었다. 이후 최대 진행 간격은 **30.669ms**, 마지막 진행부터 마지막 데이터까지의 꼬리 구간은 최대 1.004ms였다. 시작·중간·끝을 포함해 100ms 이상 공백은 없었다.

서버의 ACK 송신은 Mac의 ACK 수신을 뜻하지 않는다. 시각 오차 안에는 다른 진행 기록도 있어 이 수치를 실제 첫 무선 복귀 지연으로 사용하지 않는다. host PS 조건 역시 NPU나 RF가 실제 패킷을 차단했다는 증거는 아니다.

## 검증·복원·남은 작업

TCP 방향·cookie/FIN/바이트 대조, 시계·절전/연결 상태 대조, 서버 수신 CPU 기록의 **3개 분석 그룹 PASS / 0 FAIL / 0 SKIP**이다. 독립 코드 검토도 수행했다. 이는 분석 계약의 통과율 100%이며 원래 고장의 해결률이 아니다. 입력·검사기 해시와 수치는 `UPLOAD_ENDPOINT_DATA.json`에 있다.

설정 34개 해시, 진단 옵션 OFF, 기존 PS 수정 ON, 동일 부팅, 유선 관리와 핫스팟 HTTP 200을 확인했다. 서버 기록 프로세스는 종료됐고 회수 파일의 크기·SHA256은 서버와 일치했다. 단말 식별자·설정 백업·원시 패킷은 공개하지 않는다.

이 결과만으로 PS 알림을 무시하거나 링크 절전을 강제로 해제하는 수정은 하지 않는다. 별도로 확인된 NPU zero-budget 코드 결함의 수정 가능성은 독립적으로 검토하며, 그 후보를 이번 저하나 Air 멈춤의 해결책으로 아직 판정하지 않는다. 기존 r42 태그와 설치 이미지는 유지한다.
