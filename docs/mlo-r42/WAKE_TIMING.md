# r42 PS 복귀 시각과 저하 구간

이번 기록에서는 **공유 TXQ의 PS 조건이 해제된 뒤 수초간 정체했다는 증거가 없다.** 평균 599.994Mbps는 설정한 합계 목표 600Mbps이며, 최대 처리량 검사는 아니다. 최저 57.558Mbps, 500Mbps 미만 14개 구간, 0Mbps 구간은 0개다.

전역 P 1,450개는 내부 순번 누락이 없다. 대상 722개 모두 old/new 전환, 링크별 상태의 연속성, 기록된 두 PS bit와 gate 일치 검사를 통과했고 non-AQL은 모두 0이다. 보장된 전송 창의 대상 P는 652개다. 반복 같은 상태 알림은 기록되지 않으며 로그 경계 밖까지 완결성을 주장하지 않는다.

- 전송 창 안에서 닫힘과 재개가 모두 관측된 gate 구간은 **163개**, 합계 **12.625984초**, 최장 **202.310ms**다.
- 14개 저하 구간의 총 14.005510초 중 gate=1과 겹치는 시간은 **10.821063–11.691165초(77.263–83.475%)**다. 데이터 시작의 1.302135초 범위와 공유기 시계 오차를 하나의 공통 이동으로 계산했다.
- 마지막 1→0 gate 해제는 연결 나이 **37.860440–37.861440초**, TCP 상대 **25.273989–26.591968초**다. 그 뒤에도 gate=0 상태 기록은 있으므로 ‘마지막 gate=0 기록’과 구분한다.
- 마지막 저하 구간 종료는 TCP **26.000269초**로, 위 해제와의 차이는 **-0.591699–0.726280초**다. 순서가 겹쳐 짧은 복귀 지연의 부호도 확정할 수 없다. 해제 뒤임이 확실한 첫 전체 구간 **27.001869–28.008031초**에는 **1432.962Mbps**가 수신됐다.
- 마지막 native scan API 완료 뒤에도 최종 gate 해제까지 **4.544204–4.560048초**가 남았다. API 완료를 무선 복귀 시각으로 쓰면 이 기간을 잘못 분류한다.

서버 자체 상대 10–27초에 재전송 **2,718/2,734회**, Cwnd 표본 범위는 **149,504–1,174,405.12 bytes**다. 서버 27–30초는 재전송 0회이고 수신 측에서는 목표를 넘는 따라잡기 전송이 보인다. 서로 다른 상대 시계와 반올림 때문에 이를 정확한 마지막 wake의 TCP 인과로 환산하지 않는다.

`mt7996/mcu.c`의 P는 `mt76_sta_ps_transition()` 다음에 기록된다. awake 경로는 PS bit를 지우고 station TXQ와 worker를 예약한다. 로그는 worker 실행 완료나 성공한 무선 송신을 기록하지 않는다. 특히 이번 네 데이터 flow는 PPE/NPU 가속 경로이며, 이 host gate 함수를 패킷마다 실행하지 않는다. 따라서 위 수치는 **연속된 host PS 상태로 계산한 predicate 점유 시간**이지 실제 가속 패킷 차단 시간이나 RF dwell이 아니다.

반복 PS 상태는 저하 구간 대부분과 겹치지만 모든 저하를 이것 하나로 귀속하거나 NPU를 정상 판정할 수 없다. 원래 Air 증상 해결 근거도 아니다. 이 결과로 새 wake 패치를 정당화할 수 없다. 잔여 지연을 주장하려면 다음 최소 증거는 endpoint ACK/SACK와 첫 성공 post-wake 송신 시각의 결합이며, 현재 1초 처리량·P 알림만으로 송신자·펌웨어 큐·수신자를 분리하지 못한다.
